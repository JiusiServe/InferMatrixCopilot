# prepare_evidence.py — Evidence Plan Preparation and Review Lifecycle

<!-- kb:knowledge owner=feature-ppt-evidence-preparation facet=configuration pin=f0a69728c96b5961d993449f1a901cbd2f4dac5b verdict=pass -->

**Plan fields and CLI flags with their defaults**

The plan supplies `asset_root` and `analysis_root`, defaulting to `<project>/assets` and `<project>/analysis`; both must resolve inside the project root or the run exits 1 (L309–L316). Per-item paper selectors default `min_confidence` to 0.55 and `include_caption` to false, which picks `image_path` over `image_with_caption_path` (L95–L102, L156–L157). Retry semantics are constrained: `--force` or an explicit `--item` triggers preparation only when the item's status is one of `planned`/`acquiring`/`needs-manual` (PREPARABLE_STATUSES) and only in a non-review pass; a bare run without selection prepares only `planned` items (L52–L53, L322–L345).

**Status/review lifecycle across route families**

For file-bearing routes the lifecycle is gated: `--approve` requires the destination file to exist and sets status `ready` with review `approved`; `--used` additionally requires review status `approved` and marks status `used` (L236–L253). Native routes (`native-chart`, `native-drawing`) bypass these file and approval checks on both actions — they go straight to `ready`/`used` with review `not-required` (L231–L247). Failed or ambiguous preparation lands in `needs-manual` with review `pending`, e.g. ambiguous paper selection (L148–L154) or any per-item exception (L346–L348).

**Automatic selection versus human visual gates**

Inference / 设计推断（非作者历史意图）：

Paper-figure selection scores candidates by confidence (default floor 0.55), +2 for an exact normalized label match and +0.5 per caption-keyword hit; automatic selection succeeds only when there is a selector (label or keywords) or exactly one candidate, and either a sole ranked candidate or a top score exceeding the runner-up by more than 0.15 — otherwise the item is marked `needs-manual` for human review against the contact sheet (L95–L125, L148–L154). AI illustrations are deliberately kept manual: the script only writes a prompt file and warns that AI cannot serve as factual evidence (L216–L226, and the module docstring L4–L7). The confidence floor is a narrowing filter only; the code comment states approval remains the hard visual gate (L99–L101). These intent statements are design rationale from the source comments, not independent documentation.

**CLI surface and exit behavior**

`main()` accepts a positional `project` plus `--plan` (default `evidence-plan.json`), repeatable `--item`/`--approve`/`--used`/`--reject`, and `--force` (L294–L302). It returns 1 with a logged error when the plan file is missing (L305–L307) or when `asset_root`/`analysis_root` resolve outside the project root (L311–L316); per-item preparation failures do not set the exit code — the run still ends with `return 0`, reporting them as warnings in the completion line (L346–L353). Uncaught exceptions elsewhere (e.g. JSON parsing at L308, `save_plan` at L350) propagate and terminate via `raise SystemExit(main())` with a nonzero status.

**Selective dispatch and review pass structure**

Per item, `main()` first enforces path containment for path-bearing routes (L328–L331), then branches: if `--approve`/`--used`/`--reject` names were given (a review pass), it calls `use_item`, `approve_item`, or writes a `rejected` review without invoking any route handler (L332–L338, L322–L323). Route dispatch through `prepare_item` happens only in a non-review pass, and only for in-scope items whose status is in `PREPARABLE_STATUSES` (`planned`/`acquiring`/`needs-manual`) and that are `planned`, explicitly re-selected, or forced (L339–L345). Any exception inside this loop downgrades the item to `needs-manual` with a `pending` review rather than aborting the run (L346–L349).

**Runtime gates on review actions and asset copies**

Review actions validate state at runtime: `approve_item` raises `FileNotFoundError` if the destination asset is missing, and `use_item` additionally requires `review.status == "approved"` before setting status `used`; both native routes (`native-chart`, `native-drawing`) bypass these checks (L231–L253). For copies, `copy_asset` raises when the source is missing, and when the destination exists with different content it raises `FileExistsError` unless `--force`; with identical content it returns early, but with `force` set it still performs `shutil.copy2` (L68–L76). No test entry points for this script appear in the shown inputs.
