# skill-gen CLI（sop-text / url-fetch 子命令）

<!-- kb:knowledge owner=feature-skill-generator-cli facet=api pin=f0a69728c96b5961d993449f1a901cbd2f4dac5b verdict=pass -->

**命令行入口与子命令契约**

CLI 通过 `python3 .../scripts/skill_generator_cli.py` 调用，argparse 定义两个必选子命令：`sop-text --sop-file <Path>`（可选 `--out-text`、`--print-raw-chars`）和 `url-fetch --url <str>`（可选 `--out-json`）。handler 返回 int 作为进程退出码；文件不存在或 URL 为空返回 2。`sop-text` 仅输出纯文本（复用 `skill_gen.sop_parser._extract_raw_text`），明确不产出 SOPStructure JSON；`url-fetch` 输出 `FetchedPage` 的 JSON 数组（dataclass 经 `asdict` 序列化），写到 `--out-json` 或 stdout。脚本必须以绝对路径调用，不依赖 cwd。

**分层结构与数据流**

CLI 是薄壳：`main()` 配置日志并把脚本目录追加到 `sys.path` 尾部（避免遮蔽 stdlib），然后 `asyncio.run` 进入子命令 handler；重依赖（skill_gen 各模块）在 handler 内延迟导入。`url-fetch` 数据流为 CLI → `url_ingest.fetch_pages_from_url`（router）→ 按 URL 形态分发到 `fetch_wechat_article` 或 `fetch_web_page` → 各自解析 HTML 并返回 `List[FetchedPage]`（通常一个元素）。`url_ingest.__init__` 另提供 `validate_fetch_and_flatten`：先做 SSRF 校验（`check_url_allowed_for_fetch`）再抓取并拼平为单一文档字符串——CLI 路径未调用该校验，属上层组合入口。

**命令行参数与后端抓取默认值**

`sop-text` 需要 `--sop-file`（Path），`--print-raw-chars` 优先于 `--out-text`：置位时只向 stdout 打印字符数并立即返回，不会写文件；否则有 `--out-text` 就写 UTF-8 文件，否则打印原文。`url-fetch` 需要 `--url`，有 `--out-json` 写文件、否则打印 JSON。两个后端模块各自默认 `DEFAULT_TIMEOUT = 30.0` 和 Chrome/120 User-Agent；router 仅当调用方显式传 `timeout`/`user_agent`（非 None）时才覆盖默认值。

**URL 分发与正文抽取行为**

`fetch_pages_from_url` 按 URL 形态分发：匹配 `mp.weixin.qq.com` 等 `/s` 链接走 `fetch_wechat_article`，其余 HTTP(S) 走 `fetch_web_page`；通用页面在 `MAIN_CONTENT_SELECTORS` 候选中选取文本量 >100 字符的节点，失败时降级为 body 内 >200 字符的容器，最终回退到整个 body，且抽取出的正文至少 50 字符否则报错。WeChat 抓取器要求页面存在 `div#js_content` 节点，抽取为空即抛错；两者都输出单个 `FetchedPage`（含 title、source_type、metadata）。
