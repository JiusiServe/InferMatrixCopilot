# ascend-moe-optimizer-trace-analyzer CLI 主流程

<!-- kb:knowledge owner=feature-ascend-trace-analysis-pipeline facet=features pin=f0a69728c96b5961d993449f1a901cbd2f4dac5b verdict=pass -->

**核组归因、重叠与空洞分析**

除 phase/category/name/tid 等常规汇总外，组件针对 Ascend 1C2V 场景做了核组归因：从 tid 形如 `typeN_coreN` 中提取 core_type，映射到 `cube`、`vector_recv`、`vector_send` 三个核组，并输出按核组切分的 phase/category 汇总。`build_overlap_summary` 计算所有 phase 两两的区间重叠（含 overlap_ratio_min 等多口径），`build_bubble_summary` 针对 processing/dispatch_gmm1/gmm2_combine 三个父 phase 计算子阶段未覆盖的空洞（bubble）。自动诊断据此产出阈值化 findings（如 wait 占比、dispatch_gmm1 与 gmm2_combine 的流水覆盖强弱）。

**CLI 入口、参数与错误契约**

公共入口是 `app.py` 的 `main()`（`__main__` 下以 INFO 级别初始化 logging 后调用）。CLI 由 argparse 定义：必填 `--trace`，可选 `--phase-map`（默认 `config/phase_map.yaml`）、`--output-dir`（默认 `output`）、`--top-n`（默认 20）、`--llm-analysis`、`--llm-command`、`--llm-timeout`（默认 120 秒）。运行前 `validate_inputs` 对 trace 与 phase map 做存在性检查，缺失时抛 `FileNotFoundError`。LLM 分析是可选支路：`--llm-analysis` 开启后命令经 `shlex` 解析并作为子进程执行，`run_llm_command` 显式捕获 shlex `ValueError`、`FileNotFoundError` 与 `subprocess.TimeoutExpired`，分别返回 error/timeout 状态字典；主流程仅在 `--llm-analysis` 开启且 status 非 ok 时记录 warning，未开启则返回 disabled 状态。子进程其他异常类型不在所示捕获范围内。

**入口存在性检查与运行结束日志**

运行前的显式校验只有 `validate_inputs` 的两个文件存在性检查（trace 与 phase map），缺失即抛 `FileNotFoundError`，所示代码中没有对输出产物的一致性回读。运行结束后 `log_run_summary` 在 INFO 级别记录 overview 计数（实例数、phase/name/pid/tid 数、核组、wall time）、diagnosis headline，以及 phase/category 摘要的前 10 行和全部 core group 行（core_group_summary 本身按 cube/vector_recv/vector_send 的固定组序排列，不是按 union_us 全局排序），仅作日志呈现，不构成第二次校验。

**CLI 参数与 phase map 加载**

CLI 仅 --trace 必填；可选 --phase-map（默认 config/phase_map.yaml）、--output-dir（默认 output）、--top-n（默认 20，控制报告与图表行数）、--llm-analysis（开关）、--llm-command（默认 None）、--llm-timeout（默认 120 秒）。命令解析优先取显式 --llm-command，否则回退环境变量 TRACE_ANALYSIS_LLM_CMD；命令经 shlex.split 拆分，若拆分结果为空 argv（例如仅空白字符串，此时 `command or env` 为真值、不再回退环境变量）则返回 not_configured 状态。phase map 加载优先用 PyYAML 的 safe_load，PyYAML 缺失时退回一个只支持固定缩进结构的自研 YAML 子集解析器。

**主流程：解析、映射、九张汇总表与诊断支路**

main() 按固定顺序组织数据流：parse_trace_json 统一解析 Chrome JSON 的 ph=='X' 完整事件与 B/E 栈配对事件（按 pid/tid/name 配对，孤立或时间反常的丢弃）；PhaseMapper 用 YAML phase 规则把事件名映射为 phase；build_phase_instances 只保留成功映射的区间行并派生 category/core_group 等字段。随后构建九张汇总表（phase/category/core_group/phase_core_group/category_core_group/name/phase_tid/overlap/bubble）与 overview；自动诊断接收 overview 加其中八张表（不含 phase_tid_summary）。图表与 LLM 分析是可选支路，最终统一落到 output 目录的 CSV、report.md 与 summary/diagnosis JSON。
