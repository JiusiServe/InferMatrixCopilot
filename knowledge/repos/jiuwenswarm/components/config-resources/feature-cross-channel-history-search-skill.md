# Cross-Channel Session History Search Skill (search_history.py)

<!-- kb:knowledge owner=feature-cross-channel-history-search-skill facet=api pin=f0a69728c96b5961d993449f1a901cbd2f4dac5b verdict=pass -->

**CLI Entry Point and Invocation Contract**

The skill is a standalone Python CLI (`main()`, exit code 0) run via `python search_history.py`. Public inputs are argparse flags: `--sessions-root`, `--channel`, `--session-id`, `--query` (space-separated keywords, all must match), repeatable `--keyword`, `--start`/`--end`/`--at` time expressions, `--window-minutes`, `--timezone`, `--limit`, `--max-sessions`, and `--auto-expand`/`--no-auto-expand`. Output is not structured data but a fixed-marker plain-text report on stderr (SKILL id line, `HISTORY_SEARCH_SUMMARY_BEGIN/END` block, then `HISTORY_CONTEXT_BLOCK_BEGIN/END` with numbered hits), designed to be greppable in `mcp_exec_command` echo/logs.

**Flags, Defaults and Precedence**

Documented defaults: `--window-minutes` 120, `--timezone` Asia/Shanghai, `--limit` 20, `--max-sessions` 200, `--auto-expand` true (disable with `--no-auto-expand`). Time window precedence: explicit `--start`/`--end` (a missing side defaults to now-24h / now) wins over `--at` (center ± window/2); with none, the last 24 hours is used. Sessions-root precedence: CLI flag, then `get_agent_sessions_dir()` from jiuwenswarm, then `JIUWENSWARM_DATA_DIR/agent/sessions`, then `~/.jiuwenswarm/agent/sessions`. Without `zoneinfo`, timezone falls back to a fixed UTC+8.

**Read-only CLI scan over per-session history.json files**

The skill is a standalone Python CLI whose single flow is: argparse parsing → timezone/time-window resolution → enumerate session directories → read each directory's history.json → filter records by time, non-empty content and keywords → sort by timestamp descending → emit a fixed-marker plain-text report on stderr. Channel filtering matches either a session-id prefix `{channel}_` or an exact equality with the channel; an explicit `--session-id` takes precedence over the channel filter. Malformed files are skipped, but a history.json that is a JSON list containing dicts keeps its dict items even when some entries are non-dicts.

**Cross-channel keyword/time search with capped scan and 72h auto-retry**

The script searches session folders under the resolved sessions root, but only the most recently modified `--max-sessions` directories (default 200) are scanned; older sessions are silently out of scope. When the initial search yields no hits and auto-expand is enabled (default) and neither `--start` nor `--end` was given, the window is replaced with the 72 hours ending at now and the search reruns — note this replaces rather than widens an `--at`-centered window. Hits carry session_id, role, channel_id, timestamp and request_id.

**Self-describing stderr report; no tests shown**

The script's only built-in verification surface is its report: when it reaches emission it prints the `SKILL=cross-channel-history-retrieval` marker plus a `HISTORY_SEARCH_SUMMARY_BEGIN/END` block with timezone, window, filters, scanned_sessions, scanned_records, hit_count and auto_expanded, followed by a numbered hits block. However, reaching the report is not guaranteed — argument parsing, ZoneInfo lookup and time parsing run before it and can fail — and scanned_sessions is incremented before checking for history.json, so the counters alone do not prove session data was actually read. No test entry points for this skill appear in the shown inputs.

**Bounded substring scan with capped output, at the cost of recall and silence on errors**

Inference / 设计推断（非作者历史意图）：

The skill trades index-free simplicity for bounded work: session directories are sorted by mtime and only the newest `--max-sessions` (default 200) are scanned, records are filtered by case-insensitive all-keyword substring match on `content`, hits are sorted by timestamp descending and truncated to `--limit`, and unreadable or non-JSON history.json files are silently skipped rather than reported. The cost is recall: older sessions fall out of scope, records without a parseable timestamp or with blank content are skipped before keyword matching, and no error surfaces for corrupt files. A default 72-hour auto-expand retry (only when no `--start`/`--end` was given and the first pass found nothing) trades a second full scan for better recall on empty results.
