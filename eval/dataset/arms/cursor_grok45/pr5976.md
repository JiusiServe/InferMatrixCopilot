### P1 — Double-seed of `num_stale_output_tokens` on `replace_streaming_prompt`

**`vllm_omni/core/sched/omni_ar_scheduler.py:627-670`** + **`vllm_omni/core/sched/omni_scheduler_mixin.py:105`**

**Trigger:** MiniCPM-o (and any stage) streaming update with `meta.replace_streaming_prompt=True` while `num_in_flight_tokens > 0`.

**Current behavior:** `_update_request_as_session` always does:

```627:629:vllm_omni/core/sched/omni_ar_scheduler.py
        in_flight_tokens = int(getattr(session, "num_in_flight_tokens", 0) or 0)
        if in_flight_tokens > 0:
            session.num_stale_output_tokens += in_flight_tokens
```

then, on the replace path, calls `_replace_streaming_session`, which seeds again:

```105:105:vllm_omni/core/sched/omni_scheduler_mixin.py
        session.num_stale_output_tokens += int(getattr(session, "num_in_flight_tokens", 0) or 0)
```

With `num_in_flight_tokens=2`, the counter becomes **4**. After the two late frames drain, **2** leftovers remain and the drain swallows the new segment’s first valid frames — the same hole this PR’s `c2b65233` / stale-drain tests were written to close.

**Impact:** Corrupted codec/audio on MiniCPM-o (and any `replace_streaming_prompt` consumer). Stage-0 seed-TTS path is not covered by this bug (tests hit `super()` without replace), which matches “drain fix landed but WER still open” only partially — this is a separate, reachable regression.

**Fix:** Seed once. On the AR replace branch, skip the pre-seed (mixin already seeds); keep the pre-seed only for the early-return / `super()` paths. Add a CPU test that sets `num_in_flight_tokens`, calls `_update_request_as_session` with `replace_streaming_prompt=True`, and asserts `num_stale_output_tokens == num_in_flight_tokens` (not `2×`).

Generation is fine: it only goes through the mixin (`omni_generation_scheduler.py:604`).
