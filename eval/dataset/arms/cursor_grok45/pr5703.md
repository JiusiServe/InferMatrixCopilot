### P1 — `fork_rng` still uses CUDA RNG state for non-CUDA devices

`vllm_omni/diffusion/models/minimax_h3/vae.py:170-176` and `:214-220`

```170:176:vllm_omni/diffusion/models/minimax_h3/vae.py
        devices = [parameter.device] if parameter.device.type != "cpu" else []
        try:
            with torch.random.fork_rng(devices=devices):
                torch.default_generator.manual_seed(MINIMAX_H3_KEYFRAME_ENCODE_SEED)
                for device in devices:
                    with self.device_module.device(device):
                        self.device_module.manual_seed(MINIMAX_H3_KEYFRAME_ENCODE_SEED)
```

`torch.random.fork_rng` defaults to `device_type="cuda"`. It saves/restores via `torch.cuda.get_rng_state` / `set_rng_state`, and that API uses **only `device.index`**, ignoring `device.type`.

So for `parameter.device == musa:0` (or `npu:0`):
- seeding goes through `self.device_module` (hopefully musa/npu),
- but the context saves/restores **CUDA index 0** (or fails on Ascend CPU+NPU builds with no CUDA generators).

That breaks the PR’s own claim that CPU and active-device RNG are restored, and it is a regression vs the old `device.type == "cuda"` gate for Ascend MiniMax H3 (`MiniMax-H3-NPU.md`: no CUDA runtime).

**Fix:** allowlist explicitly, and pass the matching type:

```python
device = parameter.device
device_type = device.type
devices = [device] if device_type in ("cuda", "musa") else []
device_mod = torch.get_device_module(device) if devices else None
with torch.random.fork_rng(devices=devices, device_type=device_type if devices else "cuda"):
    ...
    if device_mod is not None:
        with device_mod.device(device):
            device_mod.manual_seed(MINIMAX_H3_KEYFRAME_ENCODE_SEED)
```

Same change in both `encode_image` and `encode_video`.
