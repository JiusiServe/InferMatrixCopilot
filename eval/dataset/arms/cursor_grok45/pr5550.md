### P2 — Pre-RPC identity checks only cover `execute_request`

`execute_request` correctly validates every envelope **before** RPC so identity failures never cross the process boundary or get wrapped as worker errors:

```454:460:vllm_omni/diffusion/executor/multiproc_executor.py
        # Validate every envelope before selecting a dispatch path. In
        # particular, keep identity errors outside the RPC error wrapper so an
        # invalid request cannot be forwarded or converted into a worker output.
        from vllm_omni.diffusion.sched.interface import validate_new_request_data_identity

        for new_req in new_reqs:
            validate_new_request_data_identity(new_req)
```

But the engine’s live `execute_fn` is `execute_batch` / `execute_step`, and those paths still forward first:

```615:620:vllm_omni/diffusion/executor/multiproc_executor.py
        result = self.collective_rpc(
            "execute_model_batch",
            args=(scheduler_output, self.od_config),
            unique_reply_rank=0,
            exec_all_ranks=True,
        )
```

```646:656:vllm_omni/diffusion/executor/multiproc_executor.py
    def execute_step(self, scheduler_output: DiffusionSchedulerOutput) -> BaseRunnerOutput:
        """Forward step-mode scheduler output to worker execute_stepwise RPC."""
        ...
        result = self.collective_rpc(
            "execute_stepwise",
            args=(scheduler_output,),
            ...
        )
```

**Trigger:** `max_num_seqs > 1` fused request-batch, or step mode, with envelope/`req`/`metadata.request_id` mismatch.  
**Impact:** Invalid allocation envelopes are pickled to workers; failure becomes an RPC/`RuntimeError` instead of a local `ValueError`, contrary to this PR’s stated invariant. Single-request waves are fine (`execute_batch` → `execute_request`).  
**Fix:** Run the same `validate_new_request_data_identity` loop at the top of `execute_batch` and `execute_step` (before any `collective_rpc`). Add a regression test on the multi-req `execute_batch` path mirroring `test_request_rpc_rejects_envelope_request_identity_mismatch`.
