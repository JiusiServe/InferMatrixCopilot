### `vllm_omni/diffusion/attention/backends/flash_attn_hub.py:141` — medium / bug

Using `assert` for runtime validation of `attention_mask.ndim` is unsafe: assertions are stripped when Python is run with `-O` (optimized mode). ### `vllm_omni/diffusion/attention/backends/flash_attn_hub.py:71-103` — medium / maintainability

`FlashAttentionHubImpl` and `FlashAttention3HubImpl` are nearly identical (~150 lines each) with the only differences being the kernel name (`flash-attn2` vs `flash-attn3`) and log messages. This duplication increases maintenance burden: a bug fix or improvement applied to one class could be missed in the other. Consider extracting shared logic into a common base class or a parameterized implementation to reduce the risk of divergence.

### `tests/diffusion/attention/test_kernels_hub.py:26-27` — high / bug

Setting `sys.modules["kernels"] = None` does NOT simulate a missing package. Python's `importlib.import_module("kernels")` checks `sys.modules` first and returns the cached value (which is `None`) without raising `ImportError`. This means the `except ImportError` block in `get_diffusion_attn_backend_cls` (platform.py line 128) is never reached, so the fallback from `FLASH_ATTN_HUB` → `FLASH_ATTN` will NOT occur. The first two assertions in this test will fail.

Instead, delete the key from `sys.modules` so that the import actually fails with `ImportError`:
```python
monkeypatch.delitem(sys.modules, "kernels", raising=False)
```
Or mock `importlib.import_module` to raise `ImportError` for `"kernels"`.

Anchored to:

```
    # Temporarily hide/remove kernels module if present

```

Suggested:

```

```
