### `vllm_omni/model_executor/stage_input_processors/hunyuan_image3.py:117-119` — medium / bug

The function now defensively returns `None` when `source_outputs` is empty (line 114-115), but unconditionally accesses `ar_output.outputs[0]` on line 119 without checking if the `outputs` list is non-empty. If the AR stage produces a `RequestOutput` with an empty `outputs` list (e.g., due to an aborted or failed generation), this will raise an `IndexError`. While vLLM typically guarantees non-empty `outputs` for completed requests, the new defensive pattern for the outer list makes this blind spot inconsistent. Consider adding a guard: `if not ar_output.outputs: return None`.

Anchored to:

```
    # The orchestrator constructs this list as [parent, *cfg_companions].
    ar_output = source_outputs[0]
    output = ar_output.outputs[0]
```

Suggested:

```
    # The orchestrator constructs this list as [parent, *cfg_companions].
    ar_output = source_outputs[0]
    if not ar_output.outputs:
        return None
    output = ar_output.outputs[0]
```
