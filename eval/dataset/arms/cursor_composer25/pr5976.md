## Findings (actionable)

### 1. **P2 — Compile-cache isolation missing on headless multi-replica spawn**

`scoped_spawn_device_env` / `_scoped_replica_compile_cache_env` (`stage_engine_startup.py:922–951`) correctly isolate `VLLM_CACHE_ROOT` for `replica_id > 0`, but only when spawn goes through `_launch_omni_core_engines` / colocated `launch_stage_replica` (`1046–1065`, `1147`).

Headless paths spawn subprocesses **without** that wrapper:

- `launch_headless_llm_replica` → direct `StageEngineCoreProcManager(...)` then implicit start (`1216–1228`)
- `launch_headless_replica_group` only wraps `replica_device_env`, not compile cache (`1447–1449`)
- `launch_headless_diffusion_replica` → `StageDiffusionProcManager.launch_headless` (`1329–1342`)
- Distributed diffusion: `launch_diffusion_stage_replica` (`1587–1599`)

On a headless host with `omni_dp_size_local > 1`, replicas auto-assigned as 0, 1, … can still compile concurrently into the **shared** default cache and reproduce the TritonBundler race the PR fixed for colocated startup (build 2954).

**Change:** After registration returns `response.replica_id`, wrap headless LLM/diffusion proc `start()` in `scoped_spawn_device_env(None, None, stage_id=..., replica_id=response.replica_id)` (or set `VLLM_CACHE_ROOT` in the child from `omni_replica_id` in `stage_engine_core_proc.py:123`). Extend `test_stage_engine_startup_cache_env.py` with a headless-launcher integration test.

### 2. **P3 — `async_tokens_to_discard` is written but never consumed**

After the 0.27 migration to `num_stale_output_tokens`, assignments at:

- `omni_ar_scheduler.py:479` (segment stop)
- `omni_ar_scheduler.py:634` (streaming session replacement)

have **no readers** anywhere in `vllm_omni/`. Stale suppression is entirely via `num_stale_output_tokens` in `update_from_output` (`330–353`).

**Change:** Remove the dead assignments (and narrow tests that only assert the field is set) to avoid implying a second discard path still exists. If something external still reads it, document that contract explicitly.

---

### 3. **P3 — `stage_runtime._scoped_spawn_device_env` omits `stage_id` / `replica_id`**

`stage_runtime.py:310–313` calls `scoped_spawn_device_env(physical_devices, self._spawn_device_lock)` without replica identity. Today it is only used for device-lock acquisition before `launch_stage_replica` (which does pass `replica_id` into the actual spawn). That is easy to misuse if someone later adds spawn logic inside `_stage_device_scope`.

**Change:** Pass `stage_id` and `replica_id` through `_stage_device_scope` / `_scoped_spawn_device_env`, or rename the helper to `_scoped_device_visibility_env` so it is not confused with compile-cache isolation.

---

### 4. **P3 — Open product issue: seed-TTS WER (acknowledged in PR)**

The stale-drain fix is necessary and tested, but nightly 2957 WER (~0.39) stayed in the pre-fix band. The PR correctly tracks this as open. Do not treat the scheduler fix as closing the WER regression; continue bisecting torch 2.13 / codec-path changes in parallel.

---

### 5. **Nit — Inductor patch probe failure installs unconditionally**

`patch.py:491–494`: if the upstream-capability probe throws, the wrapper installs anyway. That is defensible (wrapper only adds `True`), but on a broken probe + future sympy API drift you could get silent no-op or unexpected behavior.

**Change:** Log at warning when the probe fails, not only on success/skip paths.
