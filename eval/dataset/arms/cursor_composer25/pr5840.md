### Findings

#### 1. Medium — Serve/Omni path still pins `rel_l1_thresh=0.2`, bypassing H3’s `0.17` default

The PR defers threshold defaulting to `TeaCacheConfig` when `rel_l1_thresh` is `None`:

```420:422:vllm_omni/diffusion/data.py
    # None defers to the model-specific TeaCache default (0.2 fallback).
    rel_l1_thresh: float | None = None
```

```96:99:vllm_omni/diffusion/cache/teacache/config.py
_DEFAULT_REL_L1_THRESH = 0.2
_MODEL_DEFAULT_REL_L1_THRESH = {
    "MiniMaxH3DiTModel": 0.17,
}
```

But `AsyncOmniEngine` still injects an explicit `0.2` whenever the user enables TeaCache without `--cache-config`:

```853:856:vllm_omni/engine/async_omni_engine.py
        if cache_backend == "tea_cache":
            return {
                "rel_l1_thresh": 0.2,
            }
```

**Impact:** `vllm serve ... --cache-backend tea_cache` (no `--cache-config`) uses `0.2` for MiniMax-H3, not the calibrated `0.17` documented in `recipes/MiniMaxAI/MiniMax-H3.md`. The PR’s own online smoke also used `0.2`, while the recipe/examples say `0.17`.

**Fix:** Stop injecting a global TeaCache default in `_get_default_cache_config` (return `{}` or `None` and let `TeaCacheConfig.__post_init__` resolve per model), or make the injection model-aware. Add a regression test for “empty cache_config → MiniMax gets 0.17”.

---

#### 2. Low — No TeaCache + Ulysses/SP coverage

TeaCache E2E is single-GPU only (`test_minimax_h3_t2va_teacache_single_gpu_smoke`). Ulysses smoke (`test_minimax_h3_t2va_ulysses8_smoke`) does not enable TeaCache. The extractor computes `modulated_input` on the full packed sequence while `run_transformer_blocks` goes through `sp_prepare` / `sp_gather` (`extractors.py:1341–1369`), which only become non-identity under sequence parallelism.

**Impact:** TeaCache + `--usp N` is untested; cache decisions and residuals may diverge under SP sharding.

**Fix:** Either document “TeaCache supported for FL2VA single-GPU / non-SP only” in the recipe/limitations, or add a multi-GPU smoke and verify extractor behavior when `ulysses_degree > 1`.

---

#### 3. Low — Weak polynomial fit (documented, but worth monitoring)

Calibration reports **R² ≈ 0.095** and RMSE ≈ 0.04 on the relative-L1 mapping. The fourth-order polynomial is a weak predictor of output error from embedding drift.

**Impact:** Not a correctness bug — A/B metrics in the PR description look acceptable at the validated workload — but threshold tuning may be less predictable outside the 107-frame / 50-step / 256×448 envelope.

**Fix:** No code change required; consider noting the calibrated workload bounds more prominently in `recipes/MiniMaxAI/MiniMax-H3.md` (duration, resolution, steps) so users know when re-calibration is needed.

---

#### 4. Nit — User-facing TeaCache docs still imply a universal `0.2` default

`docs/user_guide/diffusion_features.md` was updated, but `docs/user_guide/diffusion/cache_acceleration/teacache.md` still documents a single global default of `0.2` and does not mention model-specific defaults (e.g. MiniMax-H3 `0.17`).

**Fix:** Add a short “model-specific defaults” subsection to `teacache.md`, or link to per-model recipes.

---

### Summary

This is a well-scoped TeaCache addition: registry entry, faithful extractor, partition-aware enabler, recalibrated coefficients, and solid CPU tests. The main gap is **default-threshold plumbing** — model-specific `0.17` is implemented in `TeaCacheConfig` but overridden by `AsyncOmniEngine`’s hardcoded `0.2` on the common serve path. Secondary gaps are **missing TeaCache+SP validation** and **stale global TeaCache docs**. None of these rise to a correctness blocker for the validated single-GPU FL2VA workload, which matches an approve-with-follow-ups verdict for an already-merged PR.
