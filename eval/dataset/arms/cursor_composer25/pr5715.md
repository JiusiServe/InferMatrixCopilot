## Specific comments

### 1. `README.md:19` — News bullet is hard to scan

The 0.26.0 announcement is one long sentence covering MiniMax H3, full-duplex, layerwise offload, hardware, streaming, TTS, and quantization. Consider splitting into two bullets or using a short lead sentence plus sub-bullets so the headline features (MiniMax H3, experimental MiniCPM-o 4.5 duplex) stand out.

### 2. `README.md:21` — Cadence rollup scope could confuse readers

The consolidated history bullet lists releases through **0.22.0**, while **0.24.0** remains as its own item on line 20. That’s reasonable editorially (keep recent releases separate), but “continued this cadence” plus an enumerated list ending at 0.22 may read as if 0.24 is outside the cadence. Consider appending “(through 0.22.0)” or “with 0.24.0 and later releases continuing separately above.”

### 3. `README.md:54` and `docs/README.md:55` — Experimental feature has no pointer

“Full-duplex realtime serving … (experimental)” is accurate, but there’s no link to how to try it. Add a link to `examples/online_serving/minicpmo/README.md` or `vllm_omni/experimental/fullduplex/DESIGN.md` so readers know where to start.

### 4. `docs/configuration/README.md:5` — Version-pinned upstream link will go stale

Pinning to `https://docs.vllm.ai/en/v0.26.0/configuration/index.html` is correct for 0.26.0, but unlike most other docs links (`en/latest`), this will need a manual bump each release. Consider a short note (“match your installed vLLM minor version”) or a maintenance comment for release doc updates.

### 5. `docs/getting_started/installation/npu/npu.inc.md:62` — RC branch vs stable tags elsewhere

The “build from main” flow clones vLLM-Ascend at `releases/v0.26.0rc`, while Docker examples use `v0.26.0`. If a stable `v0.26.0` (or `releases/v0.26.0`) branch/tag exists on vllm-ascend, prefer that for consistency with the release Docker path; otherwise add a one-line note explaining why source builds track the RC branch.

### 6. `docs/getting_started/installation/gpu/cuda.inc.md:8` — Slight redundancy with installation README

The new dependency sentence duplicates `docs/getting_started/installation/README.md:3-4`. Not wrong—CUDA readers may never open the parent page—but you could shorten cuda.inc.md to “See the compatibility note above” if you want less repetition across the install tree.

### 7. `README.md` vs `docs/README.md` — News section only on GitHub README

`docs/README.md` mirrors feature/model updates but has no *Latest News* block. That’s fine if intentional, but it will drift over time unless release updates always touch both or news lives only on GitHub. Worth deciding explicitly in a follow-up.

### 8. `README.md:21` — Paper visibility reduced in news (optional)

Removing the standalone 0.14.0 bullet dropped the in-news link to the architecture paper. The Citation section still has it (`README.md:77-88`). If discoverability matters, add “see our paper” once in the consolidated history bullet.
