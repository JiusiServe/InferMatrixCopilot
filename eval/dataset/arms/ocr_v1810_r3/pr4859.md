### `vllm_omni/model_executor/models/common/ming/audio_vae.py:141-142` — critical / bug

Mutating `config.num_hidden_layers = 4` directly corrupts the shared config object that was already passed to `self.encoder = Qwen2Model(config)` at line 131. Since HuggingFace `PreTrainedModel.__init__` stores `self.config = config` (a reference, not a copy), this means `self.encoder.config.num_hidden_layers` is now incorrectly changed to 4, even though the encoder's architecture was built with the original layer count. The original code correctly avoided this by creating a separate config via `_qwen2_config({**encoder_args, "num_hidden_layers": 4})`.

Anchored to:

```
            config.num_hidden_layers = 4
            self.aggregator = Qwen2Model(config)
```

Suggested:

```
            aggregator_config = _qwen2_config({**encoder_args, "num_hidden_layers": 4})
            self.aggregator = Qwen2Model(aggregator_config)
```

### `vllm_omni/model_executor/models/common/ming/audio_vae.py:349-351` — medium / bug

The `encode_latent` method is decorated with `@torch.inference_mode()`, indicating an inference-only path. The new code introduces `torch.randn_like(mean)` noise via reparameterization, making the latent non-deterministic — the same input will produce different latents on every call. This can break reproducibility in serving scenarios (e.g., identical requests yielding different audio outputs). If stochastic encoding is intentional for diversity, consider making it configurable (e.g., a `deterministic=True` parameter) or using a fixed seed during inference.

Anchored to:

```
        mean, scale = torch.chunk(h, 2, dim=1)
        std = F.softplus(scale) + 1e-4
        latent = (mean + std * torch.randn_like(mean)).transpose(1, 2)
```

Suggested:

```
        mean, scale = torch.chunk(h, 2, dim=1)
        std = F.softplus(scale) + 1e-4
        latent = (mean + std * torch.randn_like(mean)).transpose(1, 2)  # NOTE: non-deterministic; consider deterministic path for inference
```
