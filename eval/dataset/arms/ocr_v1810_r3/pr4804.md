### `vllm_omni/model_executor/models/moss_tts/configuration_moss_audio_tokenizer_v2.py:110-115` — medium / bug

Legacy keys `attention_backend`, `codec_compute_dtype`, and `codec_load_dtype` are only popped from `**kwargs` when the corresponding new parameter still holds its default value (`"sdpa"` / `"fp32"`). If both a non-default new parameter AND the legacy key are present (e.g., a config file contains both `attention_backend` and `attention_implementation`), the legacy key remains in kwargs and is forwarded to `super().__init__(**kwargs)`, which may cause a `TypeError` or leave an unexpected attribute on the config object. These legacy keys should be unconditionally removed from kwargs regardless of whether their values are used.

Anchored to:

```
        if "attention_backend" in kwargs and attention_implementation == "sdpa":
            attention_implementation = kwargs.pop("attention_backend")
        if "codec_compute_dtype" in kwargs and compute_dtype == "fp32":
            compute_dtype = kwargs.pop("codec_compute_dtype")
        if "codec_load_dtype" in kwargs and codec_weight_dtype == "fp32":
            codec_weight_dtype = kwargs.pop("codec_load_dtype")
```

Suggested:

```
        if "attention_backend" in kwargs:
            if attention_implementation == "sdpa":
                attention_implementation = kwargs.pop("attention_backend")
            else:
                kwargs.pop("attention_backend")
        if "codec_compute_dtype" in kwargs:
            if compute_dtype == "fp32":
                compute_dtype = kwargs.pop("codec_compute_dtype")
            else:
                kwargs.pop("codec_compute_dtype")
        if "codec_load_dtype" in kwargs:
            if codec_weight_dtype == "fp32":
                codec_weight_dtype = kwargs.pop("codec_load_dtype")
            else:
                kwargs.pop("codec_load_dtype")
```

### `vllm_omni/model_executor/models/moss_tts/audio_tokenizer_v2.py:447-448` — medium / bug

The `torch.where` result broadcasts to `(B,)`, causing a shape mismatch when assigned back to `self.end_offset[:]` with `B > 1`. Either skip the `respect_exec_mask` path or handle it by checking `reset_mask.any()` before resetting the shared offset.

Anchored to:

```
    def reset(self, reset_mask: torch.Tensor) -> None:
        self.end_offset[:] = torch.where(reset_mask, torch.zeros_like(self.end_offset), self.end_offset)
```

Suggested:

```
    def reset(self, reset_mask: torch.Tensor) -> None:
        if self.respect_exec_mask:
            self.end_offset[:] = torch.where(reset_mask, torch.zeros_like(self.end_offset), self.end_offset)
        else:
            if reset_mask.any():
```
