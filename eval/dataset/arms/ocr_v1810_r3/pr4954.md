## Findings (1)

### `tests/model_executor/models/voxtral_tts/test_tts_preprocess.py:37-44` — medium / maintainability

The test bypasses `VoxtralTTSForConditionalGeneration.__init__` by using `__new__` + `nn.Module.__init__` and manually setting only `model_stage`, `model`, and `_audio_token_id`. Currently `tts_preprocess` only accesses those three attributes (plus `post_process_idx` which it sets itself), so the test is correct for now.

However, the real `__init__` also sets `has_preprocess`, `has_postprocess`, `config`, `voice_to_embedding`, `audio_generation`, `audio_tokenizer`, `requires_raw_input_tokens`, and others. If a future change makes `tts_preprocess` depend on any of these, this test will either crash with an `AttributeError` or, worse, silently pass with incorrect stub behavior.

Consider either:
1. Adding a comment explaining which `__init__` attributes `tts_preprocess` depends on, so future maintainers know to keep the stub in sync, or
2. Using a real (or more complete) `__init__` call with a minimal `VllmConfig` if feasible.
