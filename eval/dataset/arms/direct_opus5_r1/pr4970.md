## Verdict: Approve

The causal chain in the description holds up against live code at this head. I traced it rather than taking it on trust:

- `vllm_omni/entrypoints/openai/serving_speech.py:3696-3706` — the qwen3_tts-gated block reads `getattr(stage0_params, "seed", None)` off the deploy defaults and, when non-None, does `extra_args.setdefault("tts_local_seed", int(default_seed))`. With `seed` gone from the YAML this is a no-op, so no request carries `tts_local_seed`.
- `vllm_omni/worker/gpu_model_runner.py:1821-1888` — `_explicit_talker_seed` reads only `extra_args["tts_local_seed"]`, so `row_generators` is all-`None`. That skips both slow branches: the per-row scalar forward loop at `1851-1876` (the 07-04 collapse) and the `talker_kwargs["generators"]` per-row multinomial at `1887-1888` (#4889's residual ~40% gap). The batched path at `1897` is restored. Mechanism confirmed.
- Stage 1's removal is a pure no-op — `temperature: 0.0` at `qwen3_tts.yaml:87`, and the propagation block only ever reads `sampling_params_list[0]`. Side benefit: the profile's sampling params are now identical to `qwen3_tts_high_concurrency.yaml`.
- Your claim "no test references the deploy-level seed" checks out. `tests/entrypoints/openai_api/test_serving_speech.py:3347` builds its own `SimpleNamespace(seed=42)`; `tests/test_config_factory.py` has no seed assertion; no qwen3_tts e2e test asserts determinism or golden audio. No `base_config` inherits from this file (only `bagel_think.yaml` → `bagel.yaml`), so nothing downstream silently loses a seed. `docs/configuration/stage_configs.md:274/298/325` do show `seed: 42`, but that's a Qwen2.5-Omni example — no doc drift.

Two comments, neither blocking.

### `vllm_omni/deploy/qwen3_tts.yaml:53-61` — the absent seed is now load-bearing, and nothing records that

**What happens:** every other non-obvious choice in this file carries a comment explaining itself — `min_tokens: 2` points at #4962, `max_num_batched_tokens: 512` distinguishes latency tuning from correctness, `enable_prefix_caching` has a five-line rationale. After this diff, the *absence* of `seed` is equally load-bearing, but silent.

**Why it matters:** a contributor who later adds `seed: 42` back to make the default profile reproducible — an entirely reasonable-looking one-line change — silently re-lands the ~40% audio_throughput / ~2x TTFP regression, because the coupling between this YAML key and the MTP sampling path lives three files away at `serving_speech.py:3696` and is invisible from here. That's exactly how the seed survived from #1161 to #4869 unnoticed in the first place.

**Smallest fix:** one comment in stage 0's `default_sampling_params`, matching the file's existing density:

```yaml
      # No default seed: any seed here propagates to
      # extra_args["tts_local_seed"] (serving_speech.py) and forces the
      # per-row generator MTP path (~40% audio_throughput at c>=16).
      # Request-level `seed` still works. See #4963.
```

### `vllm_omni/entrypoints/openai/serving_speech.py:3696-3706` — this branch now has no in-tree producer

**What happens:** with this deletion, none of the three shipped qwen3_tts profiles (`qwen3_tts.yaml`, `qwen3_tts_high_concurrency.yaml`, `qwen3_tts_forced_aligner.yaml`) carries a `seed`. The `default_seed` branch added by #4869 is still *reachable* — a user-authored YAML with a seed hits it — so it isn't dead code to delete blindly.

**Why it matters:** its only regression test (`test_serving_speech.py:3347`) pins a synthetic `SimpleNamespace(seed=42)`, not any real config. So if the deploy→`tts_local_seed` wiring broke, nothing in the tree would notice. Either add a config-level test that drives it from an actual profile, or fold an explicit decision to drop the branch into the #4261 follow-up.

### One correction to the PR body

The description frames the change as affecting only residual-MTP sampling, but `gpu_model_runner.py:555-559` shows the default seed also put every request into `SamplingType.RANDOM_SEED` for the *main* talker sampler. Removing it returns default requests to `SamplingType.RANDOM`. Both are batched, so there's no perf delta there — but it does mean stage-0 token sampling is now non-reproducible by default too, not just the MTP residual. Worth a sentence, since it's the broader user-visible behavior change.
