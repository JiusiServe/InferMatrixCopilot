**Snapshot:** head `5793cd6f4bba`, merge-base `d7b365df6407`. PR state **MERGED**. CI: **`buildkite/vllm-omni-amd-ci` failing** (that gate already reports it). Diff: 3 files, +92/−6.

### 1. `_sleeping_tags` is engine-global while `sleep`/`wake_up` are per-stage — partial-stage wake reopens the exact crash

`vllm_omni/entrypoints/async_omni.py:936` and `:985-987`

```python
self._sleeping_tags.update([CuMemTag.WEIGHTS.value, CuMemTag.KV_CACHE.value])   # 936
...
for t in requested_tags:
    self._sleeping_tags.discard(t)                                              # 985-987
```

Both `sleep()` (`:904`) and `wake_up()` (`:941`) accept `stage_ids`, but the state they mutate has no stage dimension. Concrete path on the two-stage engine the tests already build (`tests/entrypoints/test_omni_sleep_mode.py:75-105`):

```python
await engine.sleep(stage_ids=[0, 1], level=1)   # _sleeping_tags = {"weights","kv_cache"}
await engine.wake_up(stage_ids=[0])             # discards BOTH tags -> set is empty
async for _ in engine.generate(...):            # guard at :310 passes
```

Stage 1 is still asleep, the request reaches the data plane, and you get back the `cudaErrorIllegalAddress` in `#4473` Repro B — the failure this PR exists to prevent. The mirror case also misbehaves: `sleep(stage_ids=[0])` marks the whole engine asleep, and a later `wake_up(stage_ids=[1])` is treated as a legitimate full wake.

Fix direction: key the state per stage, e.g. `self._sleeping_tags: dict[int, set[str]]`, populate only the `stage_ids` actually slept, discard only the `stage_ids` actually woken, and have the `generate()` guard reject if *any* stage entry is non-empty. Worth adding the SERV-5a acceptance case as a test: sleep two stages, wake one, assert `generate()` still raises; wake the second, assert it succeeds.

### 2. The level-2 ban is unconditional and breaks paths that work today — including `sleep()`'s own default

`vllm_omni/entrypoints/async_omni.py:944-950`

```python
if getattr(self, "_level2_sleeping", False):
    raise NotImplementedError("wake_up() after sleep(level=2) is not yet implemented: ...")
```

This is an orchestrator-wide ban, but level-2 restore is a per-backend capability and the diffusion backend implements it: `vllm_omni/diffusion/worker/diffusion_worker.py:534-539` saves `named_buffers()` to CPU on level 2, and `:585-591` copies them back in `wake_up()`. Four existing tests in the file you edited call exactly this sequence and now hit `NotImplementedError` unconditionally:

- `tests/entrypoints/test_omni_sleep_mode.py:269-272` — diffusion integrity, `sleep(level=2)` → `wake_up(stage_ids=[0])`
- `:357-377` — VRAM lifecycle audit, same pair
- `:488-493` — diffusion TP lifecycle, `engine.sleep(level=2)` → `engine.wake_up()`
- `:544-548` — `test_multistage_sleep_h100`, `sleep(stage_ids=[0,1], level=2)` → `wake_up(stage_ids=[0,1])`

Compounding it, `sleep()` defaults to `level: int = 2` (`async_omni.py:905`), so the *undecorated* call `await engine.sleep()` now permanently bricks the engine: `_level2_sleeping` is only cleared at `:990-991`, inside `wake_up()`, after the raise at `:944` — so the flag is unreachable once set, `is_sleeping()` stays `True` forever, and `generate()` stays rejected. There is no reset path short of restarting the process.

Fix direction: drop the global flag and express level-2 restore as a per-stage backend capability, checked against the `stage_ids` being woken, so unsupported stages are rejected before the worker RPC while diffusion stages keep working. If the AR-backend gap is the real concern, gate it in the AR worker's `wake_up`, not in the orchestrator. This is also the most likely candidate for the failing AMD CI gate — those tests carry `hardware_test(rocm="MI325")`.

### 3. `ERROR` ACKs still clear the sleeping state

`vllm_omni/entrypoints/async_omni.py:975-987`

```python
for ack in worker_acks:
    if ack is not None:
        await self.event_resolver.resolve(ack)
        final_acks.append(ack)          # no status check
...
for t in requested_tags:
    self._sleeping_tags.discard(t)      # unconditional
```

Both workers return a well-formed ACK with `status="ERROR"` on failure (`vllm_omni/worker/base.py:317`, `vllm_omni/diffusion/worker/diffusion_worker.py:695`) rather than raising. So a wake that fails on one rank — a cumem map failure, an OOM during restore — still clears every tag, and the very next `generate()` sails through the guard into a half-restored allocator. The log at `:992` then reports `All N/total workers reported WARM` while counting failed ACKs. Fix direction: only discard a tag once every expected ACK for it came back `SUCCESS`; on any `ERROR`, keep the state asleep and surface the failure to the caller.

### 4. `kv_cache` is asserted for stages that have no KV cache

`vllm_omni/entrypoints/async_omni.py:936`

The tag set is hardcoded regardless of stage type, but the diffusion worker only ever allocates a `weights` pool (`diffusion_worker.py:544` uses `offload_tags=("weights",)`; `:705` is the only tag branch). On a pure-diffusion engine:

```python
await engine.sleep(level=1)              # _sleeping_tags = {"weights","kv_cache"}
await engine.wake_up(tags=["weights"])   # the pairing the docstring at diffusion_worker.py:578 recommends
async for _ in engine.generate(...):     # RuntimeError: sleeping tags ['kv_cache']
```

The engine is fully warm but `generate()` is refused, and clearing it requires a wake for a pool that never existed. Derive the tag set from what the target stages actually offloaded instead of a fixed literal pair.

### 5. Smaller points

- `async_omni.py:310, 934-935, 951, 986, 990, 1001` — `_sleeping_tags` is unconditionally initialized at `:144`, so every `getattr(self, "_sleeping_tags", ...)` / `hasattr` fallback is a dead branch. It hides real `AttributeError`s and makes an already subtle state machine harder to read. Reference the attribute directly.
- `vllm_omni/diffusion/data.py:1492-1497` — `CuMemTag` is used at exactly one site (`async_omni.py:936`) while worker-side tag handling still compares raw `"weights"` literals (`diffusion_worker.py:544, 705`). Half-adopted, it's a second source of truth; either use it at the comparison sites too or keep the literals.
- `async_omni.py:312` — a bare `RuntimeError` out of the request path surfaces as HTTP 500 through the OpenAI server. A structured 409/503-style error reads better to clients, and `generate()`'s `Raises:` block (`:294-296`) wasn't updated to mention it.
- `tests/.../test_omni_sleep_mode.py:429-431` — this asserts partial wake is rejected but never asserts the positive half: that a *subsequent* `wake_up(tags=["kv_cache"])` re-admits generation. Without it the guard could be permanently-on and the test would still pass.
