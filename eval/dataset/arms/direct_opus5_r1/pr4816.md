This is pre-existing, not a regression — before the rename this path 500'd with `AttributeError: 'State' object has no attribute 'serving_tokenization'` instead. But it's the same defect the PR set out to remove, and it now survives in exactly one mode. Smallest fix, entirely inside the helper:

### 2. `tests/entrypoints/openai_api/test_serving_speech.py:2352` — the renamed tests cannot catch this class of bug

```python
mocker.patch.object(api_server_module, "base", return_value=fake_base)
```

Every test in this file goes through `_patch_api_server_base`, which replaces `api_server_module.base` wholesale. The three renamed assignments (`:2533`, `:2546`, `:2615`) do pin something real — the `getattr(raw_request.app.state, "serving_tokenization", None)` sites in `create_speech`/`create_speech_batch`/`create_audio_generate` would raise `HTTPException` instead of returning a `JSONResponse` if the names diverged. One unpatched test would fix it — build a request whose state carries `serving_tokenization` and assert `api_server_module.base(request)` returns it (no `mocker.patch.object` on `base`), or drive `_create_speech_error_json_response` end-to-end and assert a 400 `JSONResponse` rather than a raised `AttributeError`.
