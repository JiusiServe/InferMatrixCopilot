## Review: PR #4804 — [Feature] Support MOSS-TTS-Local-v1.5 Streaming

**Snapshot:** head `5d3e53170aae`, merge-base `a25636d7803a` · state MERGED · 1 failing gate `buildkite/vllm-omni-npu-ci`
**Validation run at this SHA:** torch 2.11.0+cu130 / vllm 0.26.0 preflight OK; `tests/worker/test_omni_gpu_model_runner.py` → **21 passed**. The `qwen3_tts_request_seed` → `tts_local_seed` rename is complete and consistent across producer, consumer, and tests (zero stale references remain).

**Verdict:** the streaming architecture is sound — per-frame emission, slot-based codec session state, and abort cleanup via `on_requests_finished` all hang together correctly. But there is one **P1 that plausibly explains the red NPU gate**, one silent-audio-loss path, and a robustness regression. Follow-ups warranted.

### P1 — `seq_token_counts` is now mandatory, but only the GPU dummy path was updated

`vllm_omni/model_executor/models/moss_tts/modeling_moss_tts_codec.py:260-265`

```python
token_counts = self._normalize_seq_token_counts(kwargs.get("seq_token_counts"))
if token_counts is None:
    raise RuntimeError("MossTTS codec requires seq_token_counts; ...")
```

This replaces the previous graceful fallback (`else: offsets = [0, len(ids_flat)]`) with a hard raise. The PR correctly compensates in `vllm_omni/worker/gpu_generation_model_runner.py:799` by injecting `seq_token_counts` into the dummy/profile run — but the NPU sibling was not given the same treatment. `vllm_omni/platforms/npu/worker/npu_generation_model_runner.py` sets `seq_token_counts` only in the real path at `:299`; its `_dummy_run` (`:587`) populates `runtime_additional_information` at `:777-782` and never sets `seq_token_counts`.

**Trigger:** MOSS-TTS codec stage profiling / KV-capacity estimation on NPU → `RuntimeError` before any request is served. This is the one changed semantic path that overlaps the failing `buildkite/vllm-omni-npu-ci` gate, so it is worth checking against that log before dismissing the gate as unrelated.

**Fix:** mirror the GPU line into the NPU `_dummy_run` — `model_kwargs["seq_token_counts"] = [int(num_tokens_padded)]` alongside the existing `runtime_additional_information` block.

### P1 — Codec stream-slot exhaustion silently drops audio and still returns success

`vllm_omni/model_executor/models/moss_tts/modeling_moss_tts_codec.py` — `_decode_streaming_batch()`, the `if slot is None:` branch (≈`:470`)

When `session.acquire()` returns `None`, codes are buffered into `_stream_pending_codes`; if the request then finishes without ever getting a slot, the code logs a warning and calls `_finish_stream_request(request_id, session, None)`, which discards the buffered codes entirely.

**Trigger:** any deployment where `codec_stream_slots` is below the stage-1 concurrency. `vllm_omni/deploy/moss_tts_local.yaml` happens to match them (`codec_stream_slots: 8`, `max_num_seqs: 8`), but that pairing is undocumented and unenforced, and `MOSS_TTS_REALTIME_PIPELINE` now routes through the same raw/streaming path without setting `codec_stream_slots` at all (falling back to `scheduler_config.max_num_seqs`).

**Observed behaviour:** client receives HTTP 200 with a truncated or entirely empty audio stream; the only signal is a server-side `logger.warning`. That is precisely the failure shape the streaming contract is meant to exclude — a successful response with silently missing output.

**Fix (smallest):** fail the request explicitly on slot starvation instead of dropping, or validate `codec_stream_slots >= max_num_seqs` at codec init and refuse to start otherwise.

### P2 — Defensive `max_new_frames` parsing was removed on the new local path

`vllm_omni/model_executor/models/moss_tts/modeling_moss_tts_talker.py:1462`

```python
max_new_frames = info_dict.get("max_new_frames", [-1])[0]
```

replaces a try/except that handled list, tuple, scalar, and `None`. The sibling path in the same file at `:471-477` still keeps that guard.

**Trigger:** `max_new_frames` supplied as a bare `int` → `TypeError: 'int' object is not subscriptable`; supplied as an empty list → `IndexError`. Both raise inside the model forward, killing the engine step. Serving is safe today (`serving_speech.py:1886/1905/1994` always wrap in a list), but offline `additional_information` callers are not, and the previous code explicitly supported the scalar form.

**Fix:** restore the list/scalar normalization, ideally by extracting the `:471-477` logic into a shared helper used by both paths.

### P2 — `talker_mtp` accepts sampling params and silently ignores them

`vllm_omni/model_executor/models/moss_tts/modeling_moss_tts_talker.py:~1509`

```python
audio_temperature = 1.7
audio_top_k = 25
audio_top_p = 0.8
do_sample_val = True if do_sample is None else bool(do_sample)
```

`temperature`, `top_k`, `top_p` are declared parameters and never read; `do_sample` *is* honoured. `vllm_omni/worker/gpu_model_runner.py:1868-1870` populates all four from `subtalker_sampling_params`.

**Trigger:** an operator sets `subtalker_sampling_params: {temperature: 0.8}` for MOSS-TTS Local — it is discarded with no warning, while `do_sample` in the same dict takes effect. The inconsistency is the problem, not the fixed defaults.

**Fix:** either honour the three values when explicitly provided, or drop them from the signature and document that the depth transformer's sampler is fixed to the model-card defaults.

### P3 — Seed handling is no longer model-scoped, which serializes batched decode

`vllm_omni/entrypoints/openai/serving_speech.py:3707-3715` now sets `extra_args["tts_local_seed"]` for **every** TTS model; previously the extra-arg was written only under `if self._tts_model_type == "qwen3_tts"`.

Consumer at `vllm_omni/worker/gpu_model_runner.py:1829`:

```python
if decode_batch_size > 1 and any(_explicit_talker_seed(req_id) is not None for req_id in decode_req_ids):
```

falls back to a per-row Python loop over the **entire** batch when *any* single request carries a seed.

**Trigger:** one seeded request in a batch of 8 serializes all 8 into separate `talker_mtp` calls. This newly matters because the same PR raises stage-1 `max_num_seqs` from 1 → 8 in `vllm_omni/deploy/moss_tts_local.yaml:42`.

**Fix:** scope the scalar fallback to the seeded rows only (batch the unseeded remainder), or accept it and document the throughput cliff. Also worth renaming — `tts_local_seed` now carries seeds for qwen3-tts too, so the name misdescribes its scope.
