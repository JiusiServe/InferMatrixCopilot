## 1. `tests/helpers/assertions.py:658-660` — the containment fallback lets unrelated trailing speech pass the gate (blocking)

```python
if _short_transcript_contains_expected(transcript, expected):
    print("short speech containment check passed")
    return
```

`_short_transcript_contains_expected` (lines 47-62) accepts any transcript that contains the expected text and has **up to 2 arbitrary extra words**, for any expected text ≤ 15 characters. It does not check that the extra words are *repeats* of the expected words, which is the only failure mode the docstring claims to rescue.

Reproduced against the live helper at this SHA:

```
'how are you sorry'  vs expected 'how are you' -> cosine 0.609 (< 0.9) -> GATE PASSES
'hello there sorry'  vs expected 'hello'       -> containment True
```

`'how are you sorry'` is a genuine model artifact — the TTS spoke a word that was never in the input — and it failed this assertion before the PR. It now passes. With a 1-word input like `"Hello"` (the very fixture the module docstring cites), the gate accepts *two* fully unrelated words. This is the same class of defect as the `I don't know, sorry.` output that motivated the PR; that specific string is still caught only because it happens not to contain the expected text.

Two aggravating factors at the same call site:

- The fallback is **unconditional**. Unlike `transcript_escalation_model`, which tests opt into, this runs for every caller. The only caller is `assert_speech_response` (line 738), driven by `request_config["input"]` — so every speech e2e test across every model with a short input string is now looser, not just Voxtral.
- It runs **before** escalation. An opted-in test that would have been adjudicated by whisper `large-v3` now short-circuits on the weaker containment check, so the strong-ASR verdict is never obtained.

**Smallest fix:** require the extra words to be repeats rather than allowing arbitrary ones — e.g. assert `set(transcript_words) <= set(expected_words)` in addition to the containment and word-delta checks. That still accepts `"how... how are you"` (the target case) while rejecting `"how are you sorry"`. Additionally, move the call below the `escalation_model` block so opted-in tests keep their strong-ASR adjudication, and consider gating the fallback behind an opt-in request_config key so unrelated models' gates are unaffected.

Please also extend `tests/helpers/test_assertions.py` with a negative case in this shape — the two added tests only cover a clean repeat and a fully-unrelated transcript, and neither pins the "expected text present plus unrelated extra word" boundary that the helper actually governs.

## 2. `vllm_omni/model_executor/models/voxtral_tts/voxtral_tts.py:212-217` — nested read consumes without clearing (low)

```python
codes = info_dict.get("codes")
audio_tokens = codes.get("audio") if isinstance(codes, Mapping) else None
if audio_tokens is None:
    audio_tokens = info_dict.pop("audio", None)
```

The legacy path `pop`s (consume-and-clear); the new nested path `get`s and leaves `codes["audio"]` in place. `info_dict` here is the live `model_intermediate_buffer[req_id]` entry (`gpu_model_runner.py:1717`), returned as `update_dict` and merged straight back at line 1765, so the frame persists.

On any step where `tts_postprocess` (line 239) emits nothing — `multimodal_outputs` not a `Mapping`, or `codes.audio` absent — the *previous* step's frame is silently re-embedded instead of the branch falling through. Steady-state decode always writes a frame so this does not fire today, which is why I'm scoring it low rather than blocking, but the asymmetry is a latent trap and the fix is one word: `audio_tokens = codes.pop("audio", None)` (guarding for a non-mutable mapping if that's a concern).

The core fix itself is right: `codes.audio` is exactly what `tts_postprocess` writes at line 246, `Mapping` is already imported (line 1), and the `isinstance` guard makes the read safe against a missing or non-mapping `codes`. I confirmed the audio_generation stage is upstream of audio_tokenizer, so no inbound inter-stage payload can seed `codes.audio` before prefill and steal the `voice` branch.
