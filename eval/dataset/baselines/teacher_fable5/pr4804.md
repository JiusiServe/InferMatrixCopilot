# Review: PR #4804 — Support MOSS-TTS-Local-v1.5 Streaming

## Verdict

The core feature — true incremental streaming for MOSS-TTS-Local-v1.5 (per-frame emission from the talker, a buffered raw-chunk processor, and a persistent slot-based streaming decode session over the vendored v2 tokenizer) — is well built. I verified the trickier plumbing and it holds up: `put_req_chunk`/`emitted_any` works against the mixin's properties and defaultdict semantics, stream-slot keys (external req id) match what `on_requests_finished` receives from the stage-1 scheduler, and the `talker_mtp` refactor preserves the original sampling semantics (same frame sequence, sampled pre-forward from the previous step's hidden instead of post-forward). The abort-cleanup hook and the strict `seq_token_counts` contract are genuine robustness improvements.

However, the PR makes **three risky collateral changes outside the tested path** — to the Realtime variant, to all codec weight loading, and to the NPU runner contract — and adds ~2,400 lines of new streaming machinery with **zero new unit tests** (the only test change is the seed-key rename). The NPU CI gate is failing; item 1 below is the likely mechanism. Since the PR is already merged, these are follow-up requests.

## Major

1. **NPU dummy-run breaks the new hard `seq_token_counts` requirement.** `MossTTSCodecDecoder.forward` now raises if `seq_token_counts` is absent (`vllm_omni/model_executor/models/moss_tts/modeling_moss_tts_codec.py:260-265`). The GPU dummy/profile path was patched to inject it (`vllm_omni/worker/gpu_generation_model_runner.py:793-799`), but the NPU equivalent was not — `vllm_omni/platforms/npu/worker/npu_generation_model_runner.py` injects it only in the real path (line 299), not in `_dummy_run` (~line 780). On NPU, MOSS codec profiling will raise at startup. The `buildkite/vllm-omni-npu-ci` gate is red on this PR; mirror the GPU one-liner into the NPU `_dummy_run` and let that gate confirm.

2. **The Realtime pipeline was switched onto the streaming path without being in the test plan.** `pipeline.py:65` moves `MOSS_TTS_REALTIME_PIPELINE` to `talker2codec_raw_async_chunk`, and `modeling_moss_tts_talker.py:1142` changes Realtime emission from accumulated codes to current-frame-only. The raw processor unconditionally sets `codec_streaming=True`, and the streaming session requires the vendored v2 API (`streaming`, `_decode_frame`, `_set_streaming_exec_mask` exist **only** in `audio_tokenizer_v2.py`). If a Realtime deployment ends up on the legacy vendored codec (the fallback in `modeling_moss_tts_codec.py:735+`), `_ensure_stream_session` dies with `AttributeError`. The test plan exercises only Local v1.5. Please run a Realtime smoke test, or revert Realtime to the delay processor until it's validated.

3. **Strict weight loading defeats the codec fallback and hard-fails previously tolerated checkpoints.** `load_weights` now raises if `missing or skipped or shape_mismatches` (`modeling_moss_tts_codec.py:678-688`), but the vendored-v2-first `_build_codec` (line 727) only falls back to the legacy codec on **construction** failure. `MossAudioTokenizerV2Config.from_pretrained` accepts essentially any config.json (it defaults every field and drops `model_type` — `configuration_moss_audio_tokenizer_v2.py:105`), so an incompatible v1 checkpoint constructs a v2 model successfully and then crashes in `load_weights` where the fallback can no longer trigger. Separately, any checkpoint with benign extra tensors — previously logged as `skipped=N` and tolerated (the old log line implies this happened in practice) — now aborts startup. Suggest: catch the strict-load failure and retry with the legacy codec, and treat `skipped` (extra checkpoint tensors) as a warning rather than fatal, keeping `missing`/`shape_mismatches` fatal.

4. **Sync mode (`async_chunk: false`) is silently broken for Local and Realtime.** Both variants' `make_omni_output` now emit only the current frame (emit-gated; empty on stopping steps). The sync path selected by `stage_config.py:676` feeds the *final* stage-0 output into `talker2codec` (`stage_input_processors/moss_tts.py:50`), which will now see one frame or nothing and emit silence. Before this PR, accumulated emission made both modes work. If sync mode is intentionally unsupported for these variants, fail loudly at config-merge time instead of producing silent audio.

5. **Stream-slot exhaustion drops a request's entire audio.** In `_decode_streaming_batch`, a request that never acquires a slot buffers its codes, and if it finishes before a slot frees, everything is discarded with only a log warning — the client receives empty audio with a success status. The yaml keeps the invariant (`codec_stream_slots: 8` == stage-1 `max_num_seqs: 8`) but nothing enforces it, and slots are held for a stream's lifetime, not per step, so >8 concurrent streams is reachable under load. Suggest either deriving slots from `max_num_seqs` always (it's already the `<=0` fallback — consider removing the separate knob), or, at finish for a never-emitted request, decoding the buffered codes through a temporarily acquired/reset slot — that output is still a single valid delta since the client received nothing yet.

6. **No new tests for the new machinery.** `talker2codec_raw_async_chunk` (threshold/initial-chunk/finish-sentinel logic), `_MossCodecStreamSession` (slot acquire/release/replay), `on_requests_finished`, and the strict loader are all untested. Sibling suites (`tests/model_executor/stage_input_processors/test_qwen3_tts_async_chunk.py`, `test_fish_speech_async_chunk.py`) provide ready-made patterns for the processor at minimum.

## Minor

- `modeling_moss_tts_talker.py:1487-1490` — `talker_mtp` accepts `temperature/top_k/top_p` but hardcodes 1.7/25/0.8, so the runner's `subtalker_sampling_params` plumbing (`gpu_model_runner.py:1866-1871`) is silently a no-op for this model. Matching the model card is fine, but either honor an explicit config override or drop the dead parameters.
- `modeling_moss_tts_talker.py:1462` — `info_dict.get("max_new_frames", [-1])[0]` regresses the old defensive scalar/list handling; an offline caller passing a plain int now gets a `TypeError`. Serving always wraps in a list, but the old code guarded this deliberately.
- `modeling_moss_tts_codec.py` `_finish_empty_streaming_requests` returns an always-empty dict, yet both call sites loop over `.items()` assigning `audios[i]` — dead code that suggests behavior that doesn't exist. Return `None` and simplify the call sites.
- `modeling_moss_tts_codec.py` `_runtime_request_key` falls back to `moss-codec-stream-{index}` — a batch-index key that different requests can collide on across steps, cross-wiring decoder state. `meta.req_id` is always set on the streaming path, so make a missing id an error there instead.
- `modeling_moss_tts_codec.py:701` — `inferred_channels = 2 if "v2" in codec_path.lower()` is a path-substring heuristic; a local checkpoint dir not named with "v2" silently becomes mono. It's only the last-resort default, but log when it's used.
- `modeling_moss_tts_talker.py:1650-1663` — `make_omni_output` builds and emits `codes.ref` per request **every decode step**, but `talker2codec_raw_async_chunk` deliberately ignores ref codes (see its own comment). Dead per-step work on the critical path; remove it or gate it to the first emission.
- `stage_input_processors/moss_tts.py:245-246` — `transfer_manager.request_payload` is initialized and popped but never written; the `put_req_chunk`/`request_payload` `hasattr` shims are no-ops against the real mixin (they're properties). Trim.
- `_MossCodecStreamSession` is never `close()`d (no shutdown hook), and its per-slot fp32 ring KV caches (8 slots × 32-layer/1280-d decoder) allocate lazily on first streaming request, outside vLLM's memory accounting — worth a note in the yaml comment for small-GPU deployments.
- `pipeline.py:97` — `stop_token_ids: [151645]` hardcodes Qwen's `im_end`; prefer reading `im_end_token_id` from the model config (the talker already has it) to survive tokenizer changes.

## Good

- `on_requests_finished` wired from `_update_request_states` is the right fix for slot leaks on client aborts, and the id-keying is correct (verified stage-1 request ids equal the external req id set in `meta.req_id`).
- The `qwen3_tts_request_seed` → `tts_local_seed` rename is applied consistently (serving, runner, tests), and unconditional deepcopy of the default sampling params list when a seed is set removes a shared-state footgun.
- Replacing the `meta.finished`-as-skip-dedelay hack with two explicit processors (`talker2codec_delay_async_chunk` / `talker2codec_raw_async_chunk`) is a clear improvement.
- The v2 tokenizer port is faithful to the upstream streaming design (exec-masked ring KV caches, per-slot reset); I checked the masked-scatter/offset logic and found no porting bugs.
