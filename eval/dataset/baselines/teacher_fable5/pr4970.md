## Review of PR #4970 — Drop default seed from `qwen3_tts.yaml`

### Verdict: Approve

The change is a 2-line YAML deletion whose stated mechanism I traced end-to-end in the code, and every factual claim in the PR description checks out. This is the right fix for the regression: it removes an accidental "always-seeded" default rather than papering over the seeded path's cost, and per-request determinism remains fully available.

**Mechanism verification (all confirmed):**

1. **Propagation is real and qwen3_tts-gated.** `vllm_omni/entrypoints/openai/serving_speech.py:3696-3706` copies a deploy-level default `seed` on stage-0 params into `extra_args["tts_local_seed"]` for every request, but only when `self._tts_model_type == "qwen3_tts"`. With `seed: 42` in the yaml, *all* traffic was seeded; after this PR, no request carries `tts_local_seed` unless the caller sends `seed` (that per-request path at `serving_speech.py:3686-3694` is untouched).
2. **The perf cost of the seeded path is real.** `vllm_omni/worker/gpu_model_runner.py:1829-1844` builds per-row `torch.Generator`s from `tts_local_seed`, and `vllm_omni/model_executor/models/common/qwen3_code_predictor.py:757-764` then replaces the single batched `torch.multinomial` with a Python loop of per-row multinomials per residual-codebook step. Unseeded batches take the one-call batched path. Removing the default seed also takes stage-0 main AR sampling off vLLM's per-request-generator seeded sampling path, a smaller secondary win.
3. **Nothing in CI depends on the default seed.** The nightly perf job (`tests/dfx/perf/tests/test_tts.json`) launches with only the model name plus device overrides (so this default profile), the bench client (`benchmarks/tts/bench_tts.py`) sends no sampling seed, and both quality/WER phases are `"enabled": false` (lines 77, 184). The only unit test touching this behavior (`tests/entrypoints/openai_api/test_serving_speech.py:3347`) constructs its own params with `seed=42` and is unaffected. Config-factory tests parsing `qwen3_tts.yaml` assert nothing about seed.
4. **Consistency.** This matches `qwen3_tts_high_concurrency.yaml` and `qwen3_tts_forced_aligner.yaml`, which already carry no seed. The stage-1 deletion is additionally a pure no-op since stage 1 runs `temperature: 0.0` (greedy).

### Comments

1. **`vllm_omni/deploy/qwen3_tts.yaml:53` — default determinism silently changes; consider a comment.** Since #1161, identical requests against the default profile produced bit-identical audio (stage-0 `SamplingParams.seed=42` seeded the main talker AR sampler even before #4869 extended it to the MTP path). After this PR the default is stochastic. That's the right trade, but this yaml is the reference profile users copy from, and the seed's perf hazard is invisible in the file itself. I'd add a one-line comment where `seed` used to be (the file already documents `min_tokens` this way), e.g.: *"No default `seed`: a deploy-level seed puts every request on the per-row-generator MTP sampling path (~40% audio-throughput cost, see #4963/#4869); pass `seed` per request for determinism."* Otherwise the next person "restoring reproducibility" reintroduces the regression with no warning.

2. **`vllm_omni/entrypoints/openai/serving_speech.py:3696-3706` — the footgun remains armed for custom yamls (follow-up, not blocking).** Any user deploy config with a default seed still silently degrades all traffic onto the slow path. Until #4261 (Gumbel-max) makes the seeded path cheap, consider a startup warning when a qwen3_tts deploy config carries a default stage-0 seed. Worth tracking alongside the follow-up work the PR already names.

3. **~30 other deploy yamls still ship `seed: 42`** (qwen2_5_omni, qwen3_omni_moe, higgs, moss, fish, etc.). The `tts_local_seed` propagation is qwen3_tts-gated so they don't hit *this* MTP path, but any model with an analogous per-row-generator sampling fallback could hide the same class of regression behind its default seed. Worth a sweep as follow-up; out of scope here.

4. **Failing gates.** `buildkite/vllm-omni-amd-ci` and `buildkite/vllm-omni-npu-ci` were red at merge. The change itself is platform-neutral YAML with no AMD/NPU-specific surface, but the merge went in over failing required-or-visible checks — that's a gate/process point for the maintainers, and those two checks are the record of it.

5. **Test plan is thin but proportionate.** "Pending CI" plus a yaml-parse check is acceptable for a 2-line deletion whose mechanism is already covered by the #4889 unit tests (`tests/worker/test_omni_gpu_model_runner.py` exercises `tts_local_seed` directly). The real validation is the next nightly returning to pre-07-04 baselines — whoever watches #4963 should confirm the qwen3_tts_base/customvoice cells recover, and note the PR correctly predicts VoxCPM2 will *not* recover (separate mechanism, needs its own bisect).
