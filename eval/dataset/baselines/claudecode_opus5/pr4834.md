# Review: PR #4834 — guard generation on partial wake and ensure wake idempotency

## Verdict: **Request changes**

Two of the three fixes are sound in direction. The admission guard in `generate()` and the differential-tag filter in `wake_up()` address real failure modes (repro B and C), and the `_sleeping_tags` set is the right shape for the state that was missing.

But the PR ships three problems that are more serious than what it fixes:

1. **The level-2 `NotImplementedError` is a one-way latch that permanently bricks the engine**, and it contradicts the documented API, the default of the `/v1/omni/sleep` HTTP endpoint, and five existing tests in the very file this PR edits — including the ones the (currently red) `buildkite/vllm-omni-amd-ci` job runs.
2. **The new state is global, not per-stage**, so the exact repro-B crash the PR targets is still reachable through the `stage_ids` API that the HTTP endpoints expose.
3. **State is mutated regardless of whether the wake actually succeeded**, so a failed wake marks the engine warm and re-opens the crash path.

Details below, roughly in severity order.

---

## Blocking

### 1. `_level2_sleeping` can never be cleared — level-2 sleep bricks the engine

`vllm_omni/entrypoints/async_omni.py:944-950` raises before anything else in `wake_up()`, and the only assignment that clears the flag is `vllm_omni/entrypoints/async_omni.py:991` — *after* that raise, inside the same function. There is no other write to `_level2_sleeping = False` in the tree. So once `sleep(level=2)` runs:

- every `wake_up()` raises forever,
- `_sleeping_tags` stays `{"weights", "kv_cache"}` forever,
- `generate()` is rejected forever by the new guard at `async_omni.py:310-316`,
- `is_sleeping()` returns `True` forever.

The only recovery is a process restart. The comment at `async_omni.py:989-990` ("Only clear the level-2 flag once all tags are warm, in case partial wake support is added in the future") describes code that is unreachable today.

Blocking silent corruption is the right instinct, but the resulting state should be recoverable and explicit. Concretely, either:
- keep the raise but make it opt-out for callers that will supply weights themselves (`wake_up(..., allow_uninitialized_weights=True)`), which is the RLHF flow this repo advertises — `docs/features/sleep_mode.md` names RLHF as a target use case, and `start_weight_update`/`finish_weight_update` (`async_omni.py:1115-1128`) are no-ops today, so `collective_rpc("load_weights", ...)` is the only path and it is now unreachable; or
- keep the hard raise, but reset `_level2_sleeping`/`_sleeping_tags` on that path so the engine isn't wedged, and say plainly in the message that a restart is required.

### 2. Breaks five existing level-2 sleep→wake tests, in the file this PR edits

Every one of these does `sleep(level=2)` followed by `wake_up(...)`, and all now raise `NotImplementedError`:

- `tests/entrypoints/test_omni_sleep_mode.py:212-222` — `test_diffusion_sleep_handshake`
- `tests/entrypoints/test_omni_sleep_mode.py:269-272` — `test_diffusion_integrity_bit_level` ("Waking up (Reloading Weights)")
- `tests/entrypoints/test_omni_sleep_mode.py:357-375` — `test_diffusion_vram_lifecycle_audit`
- `tests/entrypoints/test_omni_sleep_mode.py:488-493` — pure-diffusion TP lifecycle
- `tests/entrypoints/test_omni_sleep_mode.py:544-546` — `test_multistage_sleep_h100`

None were updated. `.buildkite/test-amd.yaml:118` is the only CI entry that runs this file, with `-m "advanced_model and omni and MI325"` — that selects the module-level tests at `:488` and `:544` (they carry `@pytest.mark.omni`). That is consistent with the red `buildkite/vllm-omni-amd-ci` gate; point at that job's log to confirm, but the contradiction is visible statically.

Compounding this: the three **new** tests (`test_omni_sleep_mode.py:410-449`) are class methods carrying only `hardware_test(...)` marks. `hardware_test` (`tests/helpers/mark.py:136-148`) never adds `omni`, so the new regression tests are **not** selected by that AMD command. The net effect on CI is that this PR removes passing coverage and adds coverage that doesn't run.

Fix: convert those tests to `level=1`, or mark the level-2 ones `xfail`/`skip` with a reference to the follow-up, and add `@pytest.mark.omni` to the new tests so they're actually selected.

### 3. Docs and the default HTTP endpoint still steer users into the bricked path

- `docs/features/sleep_mode.md:56-62` — the headline Python example is `sleep(stage_ids=[0], level=2)` → `wake_up(stage_ids=[0])`. Every curl scenario in that doc uses `"level": 2`. The level table still advertises level 2 as recoverable at "Moderate" speed.
- `vllm_omni/entrypoints/openai/api_server.py:3359-3361` — `OmniSleepRequest.level` **defaults to 2**. A user who POSTs `/v1/omni/sleep` with just `stage_ids` now unrecoverably wedges the server.
- `vllm_omni/entrypoints/openai/api_server.py:3379-3391` — `omni_wakeup` doesn't catch `NotImplementedError`, so it surfaces as an unhandled 500 with a traceback rather than a 501/409. It also unconditionally removes the stage from `app.state.sleeping_stages` on success, so that set drifts from `_sleeping_tags` whenever `wake_up()` short-circuits to `[]`.

At minimum: flip the endpoint default to `level=1`, update the doc, and map the error to a proper status code.

### 4. Tag state is global, so the guard still lets the repro-B crash through

`sleep()` at `async_omni.py:934-936` writes into a single process-wide set with no notion of which stages were slept, and `wake_up()` at `async_omni.py:986-987` discards tags without consulting `stage_ids`. So:

```
await omni.sleep(stage_ids=[0], level=1)   # _sleeping_tags = {weights, kv_cache}
await omni.sleep(stage_ids=[1], level=1)
await omni.wake_up(stage_ids=[1])          # clears BOTH tags — stage 0 is still asleep
async for _ in omni.generate(...):         # guard passes → data plane → illegal memory access
```

This is reachable straight from `/v1/omni/sleep` and `/v1/omni/wakeup`, where `stage_ids` is a *required* field (`api_server.py:3359-3365`) — per-stage sleep is the primary way this feature is used. Make the state `dict[int, set[str]]` keyed by stage id (`sleep()` already resolves `stage_ids` at line 908-909), have `wake_up()` only clear entries for the stages it actually woke, and have the guard check whether *any* stage has residual tags.

### 5. ERROR ACKs are treated as successful wakes

`AsyncEventResolver.resolve` (`async_omni.py:76-107`) counts ACKs without inspecting `status`, and both worker handlers return `OmniACK(status="ERROR", ...)` on failure rather than raising (`vllm_omni/worker/base.py:311-319`, `vllm_omni/diffusion/worker/diffusion_worker.py:686-693`). `wake_up()` then discards the tags at `async_omni.py:986-987` unconditionally.

So if one TP worker fails to wake, the orchestrator marks the engine fully warm, the new guard passes, and you get exactly the CUDA illegal-access crash this PR exists to prevent — now with the added false confidence of a guard that says it checked. Since this PR makes that state load-bearing, it should gate on it:

```python
if any(getattr(a, "status", "SUCCESS") != "SUCCESS" for a in final_acks):
    # keep tags set; surface the failure instead of admitting traffic
```

The same applies to `sleep()`, where a partially-failed sleep leaves tags marked asleep that aren't — less dangerous, but it wedges the guard.

## Should fix

### 6. The idempotency fix is at the wrong layer, and the real bug is one line away

I confirmed the root cause upstream: `CuMemAllocator.wake_up` (`vllm/device_allocator/cumem.py:294-298`) calls `create_and_map(handle)` for every matching allocation with **no `is_asleep` check** — even though `data.is_asleep` is maintained right there at line 298. Double-wake re-maps mapped handles → the `cumem_allocator.cpp:145 CUDA invalid argument` in repro C.

Filtering in the orchestrator hides that from the `AsyncOmni` API only. Other callers still hit it — notably the out-of-band recovery poke at `vllm_omni/diffusion/worker/diffusion_worker.py:914`, which injects `{"type": "wake_up", "task_id": "recovery-task", "tags": None}` straight into the worker loop, bypassing the orchestrator entirely (and also desyncs `_sleeping_tags`, which will still claim the stage is asleep afterwards). Guarding in `vllm_omni/worker/base.py:215-224` and `diffusion_worker.py:570-583` — skip tags with no `is_asleep` allocations in `allocator.pointer_to_data` — fixes it for all callers and is robust to orchestrator state drift.

Related: because `wake_up()` now returns `[]` and skips the RPC whenever `_sleeping_tags` is empty (`async_omni.py:955-958`), a wake is silently dropped whenever the orchestrator's local view is stale — a fresh client, a restarted API server, or after the recovery poke above. Previously a wake always reached the workers. Worth at least a `logger.warning` rather than `info`, and ideally a `force=True` escape hatch.

### 7. Hardcoded `{weights, kv_cache}` is wrong for diffusion-only stages

`async_omni.py:936` records both tags unconditionally, but diffusion stages allocate only under `"weights"` (`diffusion_model_runner.py:191`) — there is no `kv_cache` pool. On a diffusion-only engine:

```
await omni.sleep(stage_ids=[0], level=1)
await omni.wake_up(stage_ids=[0], tags=["weights"])   # engine is now physically fully awake
async for _ in omni.generate(...):                    # RuntimeError: sleeping tags ['kv_cache']
```

The engine is blocked on a resource that never existed. Derive the tag set from what was actually slept (stage type, or worker ACK metadata) rather than assuming. The same assumption also means a future or third-party pool tag would never be woken by `tags=None`, since the request list is now the orchestrator's guess instead of a delegation to the allocator.

### 8. `getattr`/`hasattr` defensiveness is dead code masking a stale test fixture

`async_omni.py:310`, `934-935`, `951`, `986`, `990`, `1001` all defend against `_sleeping_tags` not existing, but `__init__` sets it at `async_omni.py:144`. The only object where it's genuinely absent is `tests/diffusion/test_diffusion_streaming_output.py:431`, which builds `AsyncOmni` via `object.__new__` and sets the now-removed `omni._is_sleeping = False`.

That's the wrong trade: on that mock the admission guard silently no-ops, and the fixture still carries a dead attribute name. Update the fixture to `omni._sleeping_tags = set()` / `omni._level2_sleeping = False` and use plain attribute access everywhere. `_is_sleeping` at line 431 is now the last reference to a field that no longer exists.

### 9. `is_sleeping()` semantics changed without updating the contract

`async_omni.py:995-1001` — the docstring still says "whether **all** stages are sleeping", but the implementation now returns `True` if any tag anywhere is asleep, including a weights-warm/kv-asleep engine. Callers assert on it (`tests/e2e/offline_inference/custom_pipeline/test_async_omni_collective_rpc.py:109`, `248`). Update the docstring to "any resource on any stage is asleep", or make it per-stage alongside fix #4.

## Minor

- **`async_omni.py:310-316`** — `generate()` is an async generator, so the `RuntimeError` only fires on first `__anext__`. Through the OpenAI serving path that lands mid-response as a 500 rather than a clean 4xx. Consider a dedicated exception mapped to 409 in `api_server.py`.
- **`async_omni.py:934-936`** — tags are recorded *after* the sleep RPC returns, so requests admitted while the sleep is in flight sail past the guard and reach a data plane that is mid-teardown. Setting the tags before dispatching the RPC closes most of that window. (Separately, and pre-existing: `sleep()`'s `mode: PauseMode = "abort"` parameter at `async_omni.py:905` is never used in the body — nothing drains or aborts in-flight requests.)
- **`vllm_omni/diffusion/data.py:1492-1497`** — `CuMemTag` lives in a diffusion module but is consumed by the entrypoint for LLM stages. It's consistent with `OmniSleepTask`/`OmniWakeTask` living there, so I'd leave the location, but it's used in exactly one place via `.value` while the workers still hardcode `"weights"` (`worker/base.py:196`, `diffusion_worker.py:544`). Either use it at those sites or drop it and inline the strings.
- **`tests/entrypoints/test_omni_sleep_mode.py:432-433`** — after `wake_up(tags=["weights"])` this leaves the engine with kv_cache asleep and goes straight to `shutdown()`; worth confirming that teardown path is clean, since `AsyncOmniEngine.shutdown` calls `allocator.sleep()` again (`vllm_omni/engine/async_omni_engine.py:1531-1537`).
- **`tests/entrypoints/test_omni_sleep_mode.py:446`** — `assert second_acks == []` pins an incidental return contract. `assert not second_acks` expresses the intent ("no RPC was issued") without freezing the exact empty value.

## What I'd want before merge

1. Make level-2 recoverable (or explicitly terminal *and* consistent everywhere: docs, endpoint default, tests).
2. Fix or explicitly xfail the five level-2 tests, and add `@pytest.mark.omni` to the new ones so the AMD job actually runs them — the gate is red and points here.
3. Make `_sleeping_tags` per-stage; the current global set leaves the repro-B crash reachable via `stage_ids`.
4. Gate tag clearing on `ack.status == "SUCCESS"`.

Items 6–9 can reasonably follow up, but 6 in particular is where the durable fix for repro C belongs.
