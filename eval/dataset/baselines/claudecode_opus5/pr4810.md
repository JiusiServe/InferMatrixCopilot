# Review: PR #4810 — [BugFix] Use KV cache scale mapper in custom loaders

## Verdict

**The core change is correct, but the fix is incomplete — it misses a file the PR's own test output flagged.** The three real code paths it does touch are right, and I verified the mechanics behind each claim. But `vllm_omni/diffusion/models/hunyuan_image3/hunyuan_image3_transformer.py` still calls the removed API and was quietly dropped from the test's file list instead of being fixed. Since the PR is already merged, this needs a follow-up.

**Verified as correct** (so these aren't concerns):
- Dropping the manual `loaded_weight[0]` squeeze is safe — `default_weight_loader` handles the scalar case via `param.data.copy_(loaded_weight.view(param.shape))` when `numel()==1` (`vllm/model_executor/model_loader/weight_utils.py:1236-1240`).
- Mapped names surviving the fall-through path is safe — `maybe_remap_kv_scale_name` returns the name untouched when it's already in `params_dict` (`weight_utils.py:1396-1397`), which is exactly the pre-mapped case.
- The delegation claim holds for both `hunyuan_image3.py` and `qwen2_old.py`: `AutoWeightsLoader.load_weights` scans `self.module` and its **direct children** for `quant_config` and applies `get_cache_scale_mapper()` to the stream (`vllm/model_executor/models/utils.py:409-418`). `HunyuanImage3ForConditionalGeneration` (`hunyuan_image3.py:1490`, `:2178`) and `Qwen2ForCausalLM` (`qwen2_old.py:394`, `:444`) both satisfy that. `qwen2_old.Qwen2Model` is only reachable via the `Qwen2ForCausalLM_old` registry entry (`registry.py:34`), so there's no direct-call path.
- I ran the new test file locally against vLLM 0.26.0: `8 passed`.

## Blocking follow-up

### 1. `vllm_omni/diffusion/models/hunyuan_image3/hunyuan_image3_transformer.py:2238` — still calls the removed API

```python
if self.quant_config is not None and (scale_name := self.quant_config.get_cache_scale(name)):
```

This is the same defect, in the same model family, and it is **listed as failing in the PR description's own "on current main" pytest output**. But the merged `_STALE_API_FILES` list (`tests/model_executor/models/test_kv_cache_scale_mapper.py:15-20`) contains only four entries and this file is not among them — the test was narrowed to go green rather than the file fixed.

It is reachable and it is the *delegated* case, identical to `hunyuan_image3.py`:
- `pipeline_hunyuan_image3.py:386` → `self.model = HunyuanImage3Model(self.hf_config, quant_config=quant_config)`
- `pipeline_hunyuan_image3.py:458` → `AutoWeightsLoader(self, ...)`, so the mapper is applied at the outer level and `HunyuanImage3Model.load_weights` (`:2125`) receives already-mapped names
- `hunyuan_image3_transformer.py:2049` sets `self.quant_config`, so the branch at `:2238` is evaluated for every weight on any quantized checkpoint → `AttributeError`

**Change:** delete lines 2238–2244 and replace with the same comment used in `hunyuan_image3.py:225-226`. The fall-through already calls `maybe_remap_kv_scale_name`, so nothing else is needed.

(Worth a sanity check while you're there: `od_config.quantization_config` flowing into this path should be a vLLM `QuantizationConfig` — `AutoWeightsLoader` calls `get_cache_scale_mapper()` on it unconditionally.)

## Test coverage issues

### 2. `tests/model_executor/models/test_kv_cache_scale_mapper.py` — not wired into CI, so it guards nothing

The buildkite pipelines enumerate explicit `pytest` invocations with `source_file_dependencies` (see `.buildkite/test-ready.yml`, `test-merge.yml`, `test-amd-ready.yaml`); none runs `tests/model_executor/models/` as a directory, and no step references this file. As merged, the regression test never executes in CI. Either add a step, or attach the static scan to an existing always-on CPU/lint job.

### 3. `test_kv_cache_scale_mapper.py:15-20` — hardcoded allowlist can't catch what it's for

`_STALE_API_FILES` is a fixed list, which is precisely why finding #1 slipped through. Replace with a repo-wide scan:

```python
_STALE_API_FILES = sorted(
    p.relative_to(_REPO_ROOT).as_posix()
    for p in (_REPO_ROOT / "vllm_omni").rglob("*.py")
    if ".get_cache_scale(" in p.read_text(encoding="utf-8")
)
```
…and assert the list is empty. That way a new offender fails the test instead of being invisible.

Also note `_REPO_ROOT = Path(__file__).resolve().parents[3]` (`:14`) assumes a source checkout; the test will misbehave if tests are ever run against an installed wheel.

### 4. `test_kv_cache_scale_mapper.py:100-119` — the test name promises something it doesn't do

`test_auto_weights_loader_delegated_loaders_accept_mapped_cache_scale` never constructs an `AutoWeightsLoader`. It hands pre-mapped names directly to the inner loader, so it only proves the inner loader tolerates mapped names — not the load-bearing claim, which is that the outer `AutoWeightsLoader` actually finds `quant_config` on a child and applies the mapper. That's the assumption the `hunyuan_image3.py` and `qwen2_old.py` deletions rest on, and it's the one thing untested.

Either drive a real `AutoWeightsLoader` over a small module tree, or rename the test to reflect what it checks.

### 5. `test_kv_cache_scale_mapper.py:26-36` — hand-rolled fake diverges from the real API

`_RecordingCacheScaleMapper` reimplements one suffix rule. The real return type is `vllm.model_executor.models.utils.WeightsMapper`, and `get_cache_scale_mapper()` is a `@staticmethod` — so you can call `Fp8Config.get_cache_scale_mapper()` directly with no model construction and get genuine coverage of the actual suffix/regex rules (`.k_proj.output_scale` → `.attn.k_scale`, etc.). As written, the test would still pass if upstream renamed `apply` or changed the mapper's shape — the exact class of break this PR exists to catch.

### 6. `test_kv_cache_scale_mapper.py:22-23` — MiMo case uses unrealistic names

`_SOURCE_SCALE_NAME = "layers.0.self_attn.k_proj.output_scale"` has no `model.` prefix, which sidesteps `mimo_audio_llm.py:1162-1163`'s `name = "model." + name` rewrite. Real checkpoint names do hit that rewrite (it's correct — `MiMoAudioLLMForConditionalGeneration.model` is itself a registered model with a nested `.model`, so params are `model.model.layers...`). Add a `model.`-prefixed case so the MiMo test exercises the path a real load takes.

## Minor

### 7. `mammoth_moda2.py:486-489`, `mimo_audio_llm.py:1156-1159` — redundant guard, diverges from upstream form

```python
cache_scale_mapper = self.quant_config.get_cache_scale_mapper()
if cache_scale_mapper is not None:
```

`QuantizationConfig.get_cache_scale_mapper()` is a `@staticmethod` that always returns a `WeightsMapper` (`vllm/.../quantization/base_config.py:194-202`), and `WeightsMapper` is a plain dataclass with no `__bool__` — so the check can never be False. Prefer upstream's exact idiom (`vllm/model_executor/models/glm_ocr_mtp.py:169-172`) for greppability when this API churns again:

```python
if self.quant_config is not None and (
    cache_scale_mapper := self.quant_config.get_cache_scale_mapper()
):
    weights = cache_scale_mapper.apply(weights)
```

Cosmetic, but also move the block above `stacked_params_mapping` / `params_dict` in both files so it reads as a stream transform rather than being interleaved with the dict setup.
