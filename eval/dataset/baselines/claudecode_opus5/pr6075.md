## Must fix

### 1. Line-continuation backslashes inside single-quoted JSON break three commands

`docs/user_guide/diffusion/attention_backends/trtllm.md:43`, `trtllm.md:81`, `docs/user_guide/diffusion/attention_backends/rainfusion.md:24`

```bash
  --diffusion-attention-config '{"default":{"backend":"TRTLLM_ATTN",\
    "skip_softmax":{"target_sparsity":0.65,"disabled_until_timestep":0.86}}}'
```

The `\` is *inside* the single-quoted string opened by `'{`. In POSIX shells single quotes make every character literal, including backslash and newline — there is no line continuation there. The argument that reaches the parser is `{"default":{"backend":"TRTLLM_ATTN",\⏎    "skip_softmax":...}}}`, which is invalid JSON at the stray `\`.

The pre-split version (`attention_backends.md:166-169` at the merge base) had a bare newline and worked. **Fix: delete the trailing `\` on those three lines** — the wrapped JSON is fine on its own.

### 2. Layerwise design doc claims `OffloadPlan` support that does not exist

`docs/design/feature/offloader/layerwise_offload.md:38-39`

> A DiT declares ordered block-container attributes using `_layerwise_offload_blocks_attrs` **or an `OffloadPlan`**.

`LayerWiseOffloadBackend` never reads a plan: `layerwise_backend.py:413-428` goes straight to `_layerwise_offload_blocks_attrs` with only the deprecated-singular fallback, and `get_offload_plan` is imported solely by `distributed_layerwise_backend.py:34`. `offload_plan.py:3` is explicit: *"Declarative OffloadPlan for distributed layerwise offload."*

This also contradicts two other pages **in this same PR** — `design/feature/offloader/README.md:58-61` ("Distributed layerwise offload *may instead* use a pipeline `OffloadPlan`") and `user_guide/diffusion/offloader/layerwise_offload.md:57-58` ("`OffloadPlan` is a separate declarative topology path for distributed layerwise offload"). Drop the `or an OffloadPlan` clause; the other two pages are right.
