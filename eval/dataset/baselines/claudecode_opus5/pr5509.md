## Verdict

**Approve with follow-ups needed.** The core mechanism is right: the sfs tuple ordering `(q, k, p, v)` with `num_elts = (q_blk, k_blk, 0, 1)` matches how FlashInfer actually unpacks these args (`flashinfer/prefill.py:4044-4049` — note its *docstring* at 3916-3920 claims `(q_sf, k_sf, v_block_sum, p_block_sum)`, which contradicts its own code; the PR follows the code, which is correct), `bmm1_scale`/`bmm2_scale` are consistent with per-block sfs carrying the dequant, gating the kwargs behind `self.quant.enabled` keeps older FlashInfer builds working, and resolving the quantize fn at `__init__` is the right fix for the Dynamo break. Tests pass locally (`68 passed, 7 skipped`).

What holds it back is that the config surface is wider than the implementation, in ways that fail **silently** — three distinct configurations are accepted, documented as working, and quietly produce dense BF16. I verified each by running the code.

## Blocking

### 1. Ring SP silently drops SAGE — the guard that exists for skip-softmax wasn't extended

`vllm_omni/diffusion/attention/layer.py:319-326`

```python
skip = getattr(self.attention, "skip", None)
if skip is not None and getattr(skip, "configured", False):
    raise NotImplementedError(
        "Skip-Softmax (TRTLLM_ATTN) is not supported with ring sequence parallelism: "
        "the ring path bypasses the backend, so the skip config would be silently ignored. ...")
```

The ring path delegates to `self.ring_runner.run_attention(...)` and never touches `self.attention`, so with `parallel_config.ring_degree > 1` a `quant` config is ignored exactly the way skip-softmax would be — the failure mode this guard was written to prevent. The user sees no error, no warning, full-speed dense attention, and concludes SAGE gave them 0% speedup.

Add the parallel check:

```python
quant = getattr(self.attention, "quant", None)
if quant is not None and getattr(quant, "enabled", False):
    raise NotImplementedError(
        "SAGE quant (TRTLLM_ATTN) is not supported with ring sequence parallelism: "
        "the ring path bypasses the backend, so the quant config would be silently ignored. "
        "Use Ulysses SP instead, or remove the quant config.")
```

### 2. `FLASHINFER_ATTN` is allow-listed for `quant`, but nothing consumes it

`vllm_omni/diffusion/data.py:1447-1451` permits `quant` on `FLASHINFER_ATTN`. But `FlashInferAttentionImpl.__init__` (`vllm_omni/diffusion/attention/backends/flashinfer_attn.py:54-65`) swallows `backend_kwargs` into `**extra_impl_args` and reads only `causal`/`softmax_scale` — no warning, unlike `SDPAImpl`/`FlashAttentionImpl`, which at least log `"ignoring backend_kwargs"`.

Verified:

```python
AttentionSpec(backend='FLASHINFER_ATTN', quant={'dtype_qk':'fp8_e4m3'}).backend_kwargs()
# {'quant': {'dtype_qk': 'fp8_e4m3', 'q_block_size': 1, 'k_block_size': 16}}  → dropped on the floor
```

This is compounded by the docs (`docs/user_guide/diffusion/attention_backends.md:185-188`) stating `FLASHINFER_ATTN` "reads `dtype_qk` (`float16`/`bfloat16`), `dtype_vo`, and `flashinfer_backend`", and by `tests/diffusion/attention/test_attention_config.py:65-73`, which asserts the pass-through as if it were functional.

Pick one: drop `FLASHINFER_ATTN` from the allow-list at `data.py:1447` until the consumer lands (my preference — this PR is TRTLLM-only), or have `FlashInferAttentionImpl` raise/`warning_once` on a `quant` key. Whichever you pick, the doc paragraph and that test should follow.

### 3. `dtype_vo`-only config is a silent no-op on TRTLLM too

`AttnQuantSpec.enabled` (`data.py:1423-1425`) is `dtype_qk is not None or dtype_vo is not None`, but `QuantConfig.enabled` (`trtllm_attn.py:129-131`) is `dtype_qk is not None`. Verified:

```python
AttentionSpec(backend='TRTLLM_ATTN', quant={'dtype_vo':'fp8_e4m3'}).backend_kwargs()
# {'quant': {'dtype_qk': None, 'q_block_size': 1, 'k_block_size': 16, 'dtype_vo': 'fp8_e4m3'}}
QuantConfig.from_backend_kwargs(...)  # enabled: False  → dense, no error
```

Same for `flashinfer_backend`, and for `dtype_vo: "int8"` combined with a valid `dtype_qk` (V is unconditionally fp8; the request is dropped without comment). `QuantConfig.from_backend_kwargs` at `trtllm_attn.py:121-127` should raise on quant keys it does not honor, rather than ignoring them:

```python
unsupported = set(q) - {"dtype_qk", "q_block_size", "k_block_size"}
if unsupported:
    raise ValueError(f"TRTLLM_ATTN quant (SAGE) does not support {sorted(unsupported)}; "
                     "V is always per-channel fp8_e4m3.")
```

Better still, do it in `AttentionSpec.__post_init__`, where the backend name is already known — including the `dtype_qk in {float16, bfloat16}` case, which currently passes config parsing and only blows up later at layer construction (`trtllm_attn.py:199-203`). Failing at config-parse time beats failing after the model has started loading.

## Should fix

### 4. Unrelated doc deletion — 86 lines removed

The two web-UI commits `0cb1d75e` and `e54759c2` delete content unrelated to SAGE from `docs/user_guide/diffusion/attention_backends.md`: **Known Limitations** (incl. the LTX-2 `CUDNN_ATTN`-under-`torch.compile` crash and its `FLASHINFER_ATTN` workaround, tracked as #3121), **Mixed backends across roles**, **Compare against FlashAttention**, **Validation Guidance**, and **Reproducing the Benchmark Table** (which points at `benchmarks/diffusion/bench_attention_backends.py` — still present in the tree). I grepped `docs/`: none of it was moved elsewhere, it's just gone. Unless this was deliberate, restore those sections.

### 5. Doc claims that don't match behavior

`docs/user_guide/diffusion/attention_backends.md:185-188`: "each reads the fields that apply and **rejects the rest**" — neither backend rejects anything today (finding 3). And "`flashinfer_backend` (see its section)" is a dangling reference — there is no `FLASHINFER_ATTN` quant section in the file.

### 6. Output dtype silently changes under SAGE

`trtllm_attn.py:301-322`. FlashInfer allocates `out` as `bfloat16` whenever `query.dtype` is fp8/int8 (`prefill.py:3950-3963`), while the dense path returns `query.dtype`. `float16` is a supported model dtype here (`data.py:957-959`), so an fp16 DiT gets bf16 back from attention only when SAGE is on — a dtype mismatch injected into the middle of the transformer block. One line closes it:

```python
return out.reshape(batch, q_len, num_q_heads, head_dim).to(query.dtype)
```

(no-op for the bf16 path).

### 7. No arch preflight for int8

The docs correctly say int8 QK kernels are SM100-only, but `__init__` (`trtllm_attn.py:198-216`) checks only FlashInfer capability. On SM103/SM120 the failure arrives as an opaque `"Missing TRTLLM-GEN kernel"` from inside the kernel launcher on the first forward — after the model has loaded. The new test at `tests/diffusion/attention/test_trtllm_attn.py:308-312` has to string-match that message to skip, which is a good signal the check belongs at init. Add a `torch.cuda.get_device_capability()` check alongside the FlashInfer checks.

## Questions / test gaps

### 8. Sequence boundaries in the quantize call

`trtllm_attn.py:297` passes `q`/`k`/`v` already flattened to `(batch*len, heads, dim)` and gives `trtllm_sage_attention_quantize` no `cu_seq_lens`, while the kernel itself receives `cum_seq_lens_q`/`cum_seq_lens_kv`. If the quantizer blocks over the flat token axis while the kernel indexes sfs per sequence, the two disagree whenever `batch > 1` **and** `kv_len % k_block_size != 0` — and a K-smoothing mean computed across the flattened batch would mix CFG branches regardless of divisibility. I couldn't verify this locally (this box has FlashInfer 0.6.14, which has the `sage_attn_sfs` params but not `trtllm_sage_attention_quantize`), so it may well be fine. But the only e2e test, `test_sage_quant_matches_sdpa` (`test_trtllm_attn.py:305-321`), uses `B, S = 2, 256` — `256 % 16 == 0`, precisely the case that can't expose it. Please add a shape like `B=2, S=250` (or 258) to that parametrization.

### 9. The "kwargs only when enabled" fix is untested

Commit `4a6ab1a0`'s behavior — dense path passes *no* sage kwargs, so old FlashInfer builds keep working — has no test. A cheap one: monkeypatch `tg.trtllm_ragged_attention_deepseek` with a recorder and assert `"sage_attn_sfs" not in kwargs` for `_impl()`. This runs on CPU, so it protects the guarantee on every CI machine, not just Blackwell.
