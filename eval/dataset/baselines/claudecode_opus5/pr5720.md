## Verdict

**Approve the MiniMax‑H3 feature; request follow‑up fixes for the shared-infrastructure changes.**

The H3-specific work is genuinely good: the partition/task model is coherent, `_transformer_for_task` + the DLO residency gate are correct in all three startup modes, weight routing is prefix-clean, and the new contract tests are unusually thorough (I ran `tests/diffusion/models/minimax_h3/` + `tests/diffusion/cache/` — 104 passed).

The risk is not in `pipeline_minimax_h3.py`. It's in the four generic call sites this PR rewired to read `_dit_modules` (cache-dit, SP, torch.compile, LoRA). `_dit_modules` has always supported **dotted paths** — `module_collector.py:110` resolves it with `operator.attrgetter` — but three of the four new consumers use a flat `getattr`. That silently drops entries for Bagel, SenseNova‑U1, Cosmos3 and SoulX‑Singer, and in one case turns a working configuration into a startup crash. Also note both `buildkite/vllm-omni-amd-ci` and `buildkite/vllm-omni-npu-ci` are red on this PR.

## Blocking

### 1. Cache-DiT now hard-fails at startup for BagelPipeline
`vllm_omni/diffusion/cache/cachedit/backend.py:41` and `:238`

`_dit_module_names` filters with `getattr(pipeline, name, None)`, so `"language_model.model"` resolves to `None` and is dropped; `enable()` then hits the new `raise ValueError(...has no declared DiT modules...)`. Pre-PR, `_default_get_pipeline_transformer` used `pipeline.transformer`, which Bagel sets as an alias at `vllm_omni/diffusion/models/bagel/pipeline_bagel.py:254`. Bagel is *not* in `_NO_CACHE_ACCELERATION` (`registry.py:332`) and ships a documented `BagelCachedAdapter`, so this is a working path today.

Reproduced against a Bagel-shaped module:
```
names: ()
RAISED: ValueError Pipeline Fake has no declared DiT modules for Cache-DiT
```

Fix: resolve with `attrgetter` like `module_collector._collect_modules` does, and fall back to `("transformer",)` rather than raising when nothing resolves — the raise converts a previously-degraded case into a fatal one for every model whose `_dit_modules` are all dotted (Bagel, `soulx_singer/pipeline_soulx_singer_base.py:63`).

### 2. Cache-DiT silently targets the wrong module for SenseNova‑U1
`vllm_omni/diffusion/cache/cachedit/backend.py:225-228`

`SensenovaU1Pipeline._dit_modules == ["language_model"]` (`pipeline_sensenova_u1.py:536`), but `_cache_dit_adapter_config` lives on `SenseNovaU1Model` (`sensenova_u1_transformer.py:638`), i.e. `pipeline.language_model.model` — which is exactly what `pipeline.transformer` aliased at `pipeline_sensenova_u1.py:565`. `_maybe_build_block_adapter`/`_maybe_get_cached_adapter_cls` now read the config off the `SenseNovaU1ForCausalLM` wrapper, find nothing, log the benign "does not declare `_cache_dit_adapter_config`" info line, and fall through to generic `cache_dit.enable_cache` on the wrong module. `SensenovaCachedAdapter` is bypassed with no error.

The new test (`test_cache_backends.py:93-116`) only exercises the flat two-transformer case, so neither #1 nor #2 is covered. Please add a case with a dotted `_dit_modules` and one where the adapter config sits below the declared attribute.

## Should fix

### 3. A local partition directory not named `FL2VA`/`Ref2VA` now crashes with a bare `FileNotFoundError`
`vllm_omni/diffusion/models/minimax_h3/pipeline_minimax_h3.py:129-131`, `:149`, `:561-562`

Partition detection keys on the *directory name*. A user who did `hf download ... --include 'FL2VA/*' --local-dir /models/h3-fl2va` and pointed `--model` at a flattened copy gets `partition="combined"` and then `read_text()` on `<dir>/FL2VA/model_index.json`. Verified:

```
partition: combined
root: /tmp/.../h3-fl2va
model_path: /tmp/.../h3-fl2va/FL2VA exists: False
```

Pre-PR this exact directory worked (`Path(model)/"model_index.json"` was read directly). Fix: in `_resolve_minimax_h3_model_root` / `__init__`, if `<model>/model_index.json` exists, treat `<model>` as the partition root and take the partition from its `_minimax_h3.partition` field instead of inferring it from the folder name. At minimum, raise a message that names the missing file and the expected layout.

### 4. `omni_snapshot_download` gates on a filename, not on the pipeline
`vllm_omni/entrypoints/omni_base.py:80-85`

Any repo containing `modular_model_index.json` now skips download entirely, but only `MiniMaxH3Pipeline` implements self-download. This is an implicit contract between an entrypoint file-existence probe and one model's `__init__`. Prefer keying on the resolved pipeline class (e.g. a `_downloads_own_weights: ClassVar[bool]`), so adding an unrelated modular repo doesn't silently produce a server with no weights. Two smaller points on the same block: the probe passes `revision=None` regardless of `--revision`, and it adds an HF round trip to every non-modular startup.

### 5. Two `get_diffusion_model_index` callers lost their exception guard
`vllm_omni/diffusion/data.py:298-301`, `vllm_omni/diffusion/utils/hf_utils.py:101`

Both call sites previously wrapped `get_hf_file_to_dict` in `try/except`. `get_hf_file_to_dict` swallows hub/network errors and returns `None`, but a malformed index still raises `json.JSONDecodeError`. In `is_diffusion_model` that now aborts detection before Strategy 3, making the Bagel/DreamZero `config.json` fallback (`hf_utils.py:121`) unreachable. Wrap the loop body in `get_diffusion_model_index` and keep returning `None`.

### 6. `supported_tasks` fallback is asymmetric between the two partitions
`vllm_omni/diffusion/models/minimax_h3/pipeline_minimax_h3.py:582`

`ref2va_release.get("tasks", ["ref2va"])` yields `[]` when the key is present but empty, so combined mode would construct and load `transformers_ref` and then reject every `ref2va` request. Line 570 already handles the FL2VA side with `if not supported_tasks:` — use the same guard here.

## Worth considering

### 7. Default flip to combined mode doubles weights and download
`pipeline_minimax_h3.py:133-134` maps `auto → combined`. Per the recipe that's ~270 GiB on disk and both DiTs resident (`recipes/MiniMaxAI/MiniMax-H3.md:66-69`). The MUSA recipe compensates with prose only — *"do not use the modular default (combined) mode on MUSA until its two-DiT memory and performance profile is validated"* (`MiniMax-H3-MUSA.md:24-26`) — with no code-side guard. I'd either make combined explicit (`--task-type combined`, default single-partition) or emit a loud startup log stating the extra HBM/disk before the download starts. Related: `_minimax_h3_partition_for_task` accepts `"combined"` but the error message at line 139 doesn't list it.

### 8. `--task-type` typos for diffusion surface very late
`vllm_omni/config/model.py:213-218` validates only `Qwen3TTSTalkerForConditionalGenerationARVLLM`, and `serve.py:213` dropped `choices=`. `--task-type ref2v` is only rejected inside worker `__init__`, potentially after a multi-GB download. A model-arch-keyed validator table alongside `_QWEN3_TTS_TASK_TYPES` would catch it at parse time.

### 9. SP/compile dotted-path blind spot (latent, not yet firing)
`registry.py:437-439` and `diffusion_model_runner.py:283-287` have the same flat-lookup issue as #1 — `find_module_with_attr` uses `hasattr`, so Cosmos3's `"transformer.language_model"` and SoulX's `"cfm_decoder.model.diff_estimator"` are skipped. I checked: today Cosmos3 has a non-dotted second entry, and Bagel/SenseNova define neither `_sp_plan` nor `_repeated_blocks`, so behavior is unchanged — but this becomes a silent no-op the moment one of those models grows an SP plan. Apply the same `attrgetter` fix.

### 10. `cache_summary` fallback narrowed
`backend.py:40` defaults to `("transformer",)` for pipelines with no `_dit_modules`; the old code covered `transformer_2` too. A diffusers-adapter Wan MoE now loses `transformer_2` from the summary. Keep `("transformer", "transformer_2")` as the fallback.

### 11. `load_weights` contiguity coupling
`pipeline_minimax_h3.py:694-701`. The `groupby` assumption holds for `DiffusersPipelineLoader.get_all_weights` (`diffusers_loader.py:293-299` yields sources in order), so this is correct today — but it also requires `MiniMaxH3DiTModel.load_weights` to fully drain each sub-iterator, which is an invariant nothing enforces. Routing into a `{prefix: list}` dict would drop both that coupling and the "is not contiguous" error branch.

### 12. Naming
`transformers_ref` (plural noun) reads like a collection and breaks the `transformer` / `transformer_2` convention; `transformer_ref` would be clearer. It's baked into weight prefixes and `_dit_modules`, so renaming later is a migration — cheap to fix now, not later.
