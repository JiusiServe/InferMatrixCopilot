## Verdict

**Approve with follow-ups required.** The ownership split is the right direction and the mechanical refactor is faithful — every registered builder's parameter names match the new keyword-call convention (verified), the four retained builders behave identically, and `tests/model_extras` + `tests/examples/offline_inference/test_image_task_prompts.py` + `tests/diffusion/models/lingbot_video/test_request_utils.py` pass locally (42 and 73 tests).

But the PR deletes real validation and does not fully replace it: one input combination that used to fail loudly now silently produces the wrong output. Both AMD and Intel buildkite gates were red at merge, so whatever those report still needs to be cleared independent of this review.

---

### 1. Deleting the default/LingBot I2V builders removes the only media-input validation — silent wrong output (highest priority)

`vllm_omni/model_extras/registry.py:306` — with no builder registered, `build_image_to_video_prompt` now returns the envelope untouched, so `media_inputs` is forwarded verbatim. Previously `default_image_to_video_prompt` and `lingbot_video.build_image_to_video_prompt` both raised unless it was exactly `{"image": <PIL>}`.

The shared runner can produce `last_image`, `mask`, and `reference_images` (`examples/offline_inference/image_to_video/image_to_video.py:429-439`), and LingBot ignores every key except `image` (`request_utils.py:142-158` only rejects `video`/`audio`). Confirmed by running the new code path:

```
--reference-image only, LingBotVideoPipeline
  → multi_modal_data keys: ['reference_images']
  → resolve_lingbot_mode(...) == LingBotGenerationMode.T2V
```

So `--reference-image ref.png` (or `--last-image` alongside `--image`) with LingBot now silently generates plain text-to-video and discards the conditioning images. At base this raised `LingBot text-image-to-video requires exactly one PIL image input.` `examples/offline_inference/image_to_video/README.md:38` still documents "accepts exactly one first-frame image", which nothing enforces any more.

Don't just restore the old check: it was over-restrictive — Wan2.2's I2V pipeline genuinely supports `last_image` (`vllm_omni/diffusion/models/wan2_2/pipeline_wan2_2_i2v.py:470-596`) and the old default builder rejected it, so this PR silently *unblocked* Wan FLF2V. The clean fix is a declared allowlist in `_EXTRA_SPECS`, e.g. `"supported_media_inputs": frozenset({"image", "last_image"})`, checked in `build_image_to_video_prompt` with a default of `{"image"}`, so LingBot rejects extras and Wan keeps FLF2V.

### 2. The "canonical envelope" is discarded by every model that kept a builder

`registry.py:281-286` and `registry.py:321-328` **replace** the envelope with the builder's return value instead of merging. Bagel/Ming/MammothModa2 re-add `modalities` themselves, but `build_vace_image_to_video_prompt` does not (`vllm_omni/model_extras/vace.py:20-24`, `56-66`), so VACE requests still carry no `modalities` while every other I2V model now does. Behavior is unchanged from base, but the docstring "Build a model-specific T2I prompt from an example-owned envelope" overstates what the code does, and the next builder added will hit the same trap.

Suggest `return {**prompt, **builder(...)}` in both functions (builder output still wins for keys it owns, e.g. VACE's transformed `multi_modal_data`), or pass the envelope into the builders and have them update it.

### 3. `modalities=["video"]` is not a modality the stage layer knows about

Single-stage diffusion stages are registered with `final_output_type: "image"` regardless of image/video output (`vllm_omni/config/config_factory.py:592`), so the new unconditional `modalities: ["video"]` (`image_to_video.py:96`) hits the ignore path on every request. Verified:

```
get_final_stage_id_for_e2e(["video"], ["image"], [stage(final_output_type="image")])
WARNING [utils.py:721] Invalid output modality: video, ignoring it
→ 0
```

Functionally benign today — I checked the deploy YAMLs and every video pipeline (`wan2_2_ti2v`, `hunyuan_video_15`, `dreamzero`) is single-stage, so the `last_stage_id` fallback lands on the right stage. But it is a per-request WARNING on the flagship example for Wan/LTX/HunyuanVideo where there was none before, and the fallback would pick the wrong stage for any future multi-stage video model whose last stage isn't the final-output stage. Either register `"video"` as a legal stage output type for video pipelines, or keep emitting `modalities` only where a pipeline actually branches on it (Cosmos3, LingBot).

### 4. Envelope unpacking is under-validated and returns the caller's object

`registry.py:282` — `str(prompt["prompt"])` raises a bare `KeyError` on a malformed envelope and silently stringifies a structured (dict) prompt, while the I2V twin does validate its input (`registry.py:319-320`). Make the checks symmetric: raise a typed error for a missing/non-string `prompt`.

Also, both functions return the caller's dict by identity in the no-builder path — `tests/model_extras/test_model_extras.py:470-480` even asserts `is canonical_prompt`. Returning `dict(prompt)` avoids aliasing the example's mutable dict into the engine request.

### 5. Newly reachable partial-size branch in the online client

`examples/online_serving/text_to_image/openai_chat_client.py:62-67` — with `--height/--width` now defaulting to `None` (`:122-123`), the `elif` branches that fabricate a square `"{width}x{width}"` become reachable for the first time. `--width 512` alone now silently renders 512x512 instead of using the model's height. Since the Images API only accepts `size`, either require both flags together or error out when only one is given.

### 6. Smaller items

- `examples/online_serving/text_to_image/gradio_demo.py:114-120`: the comment explaining `value=100` was deleted but the value stayed. It was already stale (`run_curl_text_to_image.sh` sets no steps), and it now contradicts the PR's own "defaults come from the model" story — drop it to the model default or restate why 100.
- `tests/model_extras/test_model_extras.py`: the deleted `test_lingbot_image_to_video_prompt_builder_rejects_invalid_media` cases weren't re-homed anywhere. Add the extra-media cases to `tests/diffusion/models/lingbot_video/test_request_utils.py` as part of fixing #1 — that is exactly the coverage whose removal hid the regression.
- `examples/offline_inference/text_to_image/text_to_image.py:24,61` and `image_to_video.py:64,88`: the local builder shadows the registry function name and forces the `as build_model_*_prompt` alias plus a split import block. `build_canonical_text_to_image_prompt` locally, with the registry symbol imported unaliased, reads better and keeps the two-step call obvious at the call site (`text_to_image.py:520-529`).
- README changes check out: server defaults for `num_inference_steps`/`true_cfg_scale` really are `None` (`vllm_omni/entrypoints/openai/protocol/images.py:122,134`), so "model" in the table is accurate, and `image_to_video/run_server.sh` never honored `BOUNDARY_RATIO`/`FLOW_SHIFT` and does default `PORT` to 8099 — those doc edits are corrections, not drift.

I did not find a regression in LingBot `num_frames` despite the builder dropping it: the old prompt-level `num_frames` sat on the envelope, and `_runtime_prompt_fields` only reads fields from a *mapping-valued* `prompt`, so it was already dead code — `sampling_params.num_frames` was and remains the live path.
