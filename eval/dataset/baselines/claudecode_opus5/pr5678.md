## Verdict

**Approve for the live path; the typed projection needs changes before PR8 flips the consumer.**

The production-reachable part of this PR is small and sound: `stage_runtime.py` / `serve.py` are comment-only, `_apply_rocm_attention_backend` is a faithful extraction, and `build_legacy_engine_args_dict` fixes a real wart (it no longer mutates `stage_config.engine_args` when dropping a `None` TP size) with a test for it. I traced the three legacy readers of `tensor_parallel_size` (`_tp_size_for_stage`, `get_stage_tp_size`, `acquire_device_locks`) and all of them tolerate the key now being present-and-`None`, so that change is safe.

The typed projection is dormant today, which is the right call — but two things in it will bite at the cutover, and one of them is a user-visible regression I was able to reproduce. I ran the new suite locally (vLLM 0.26.0): `63 passed, 1 skipped`. The one red gate is `buildkite/vllm-omni-amd-ci`; see finding 4, which is adjacent enough to be worth checking against it.

## Must fix before the PR8 cutover

### 1. Ownership validation rejects ~226 engine args that work today
`vllm_omni/config/omni_config.py:872` (`_validate_stage_engine_override_ownership`)

`_COMMON_STAGE_ENGINE_FIELDS` is a hand-curated ~62-field set, but `OmniEngineArgs` has 249 fields. Any explicitly-passed arg outside the curated set is now a hard `ValueError`. Reproduced against `qwen3_tts` at this commit:

```
{'max_logprobs': 5}      -> ValueError: Stage 0 (llm_ar) has explicit engine argument(s)
                            with no structured config owner: max_logprobs
{'stage_0_swap_space': 8}-> ValueError: ... no structured config owner: swap_space
```

And these all reach `OmniEngineArgs` intact through today's legacy path (verified end to end through `filter_dataclass_kwargs`), but are unowned for LLM stages:

`kv_cache_dtype`, `block_size`, `cpu_offload_gb`, `served_model_name`, `disable_log_stats`, `num_gpu_blocks_override`, `disable_custom_all_reduce`, `structured_outputs_config`, `kv_transfer_config`, `speculative_config`, `enable_lora`, `max_num_partial_prefills`, `long_prefill_token_threshold`, `mm_encoder_tp_mode`.

`--kv-cache-dtype fp8` is the one that worries me most — it's a routine flag, it works today, and `tests/config/test_omni_config.py:236` locks in rejecting it for LLM stages (it's currently only owned as the diffusion `diffusion_kv_cache_dtype` alias).

The strictness is defensible as a design goal, and I confirmed every shipped `vllm_omni/deploy/*.yaml` passes (0 unowned keys across all 81), so nothing in-repo breaks. But user CLIs and user deploy YAMLs are unconstrained. Before the consumer switches, either give the structured stage a typed passthrough bucket for backend-owned-but-unmodeled args, or extend ownership to the full `OmniEngineArgs` surface. A note in the PR8 description that "unowned args now hard-fail" is not enough — this is a CLI compatibility break.

### 2. `scheduler_cls` diverges from legacy when `async_scheduling` arrives via CLI
`vllm_omni/config/omni_config.py:1067`

Legacy `merge_pipeline_deploy` (`stage_config.py:948-952`) resolves `sched_cls` from *deploy-only* engine args and CLI overrides are layered on afterwards in `to_omegaconf`, so legacy ends up with `async_scheduling=False` **and** `OmniARAsyncScheduler`. The typed path merges CLI into `engine` before building `scheduler_config`, so the property resolves the sync scheduler. Swept all 51 resolvable pipelines × 9 CLI override sets; with `--async-scheduling=false` or `--stage-0-async-scheduling=false`:

```
personaplex        stage 0  scheduler_cls: OmniARAsyncScheduler -> OmniARScheduler
qwen2_5_omni       stage 0,1  (same)
qwen3_tts          stage 0  (same)
step_audio_2 / step_audio_2_asr / voxtral_tts / qwen2_5_omni_thinker_only  (same)
```

The typed behavior is almost certainly the *correct* one — legacy is self-contradictory. But this PR's thesis is bit-for-bit parity, and this is an unannounced, untested runtime scheduler swap. Either state it as an intentional fix with a test asserting the new behavior, or reproduce the legacy resolution order.

### 3. Parity tests are one-directional and never exercise CLI overrides
`tests/engine/test_stage_engine_args.py:221`, `:470`

`assert {name: typed_args[name] for name in legacy_args} == legacy_args` only proves legacy ⊆ typed; extra typed keys are unchecked. The registry test (`:470`) is the strong one — it compares `_effective_backend_values` in both directions — but it always builds with `cli_overrides={"model": "/tmp"}`. That's exactly the blind spot that hides finding 2. Parametrize the registry test over a handful of representative CLI overrides (`async_scheduling`, `tensor_parallel_size`, `enable_chunked_prefill`, `gpu_memory_utilization`) and it will catch this class of drift automatically.

## Should fix

### 4. ROCm AITER backend is unreachable — and AMD CI is the failing gate
`vllm_omni/engine/stage_init_utils.py:368-376`

```python
if rocm_aiter_ops.is_enabled():
    engine_args["attention_backend"] = "ROCM_AITER_FA"
# ...
engine_args["attention_backend"] = "TRITON_ATTN"   # unconditional — clobbers the line above
```

Pre-existing (carried over verbatim from `extract_legacy_stage_metadata`), so it isn't a regression, but this PR is what turns it into a named, reused helper called from two places, which makes it the natural moment to fix: add `return` after the `ROCM_AITER_FA` assignment. Given `buildkite/vllm-omni-amd-ci` is the one red check, worth confirming against that job's log before assuming they're unrelated.

### 5. Generation-stage cache defaults are split across two layers
`vllm_omni/config/omni_config.py:1383` vs `vllm_omni/engine/stage_init_utils.py:947-948`

`_build_cache_config` hoists `disable_hybrid_kv_cache_manager=True` into the structured config for `LLM_GENERATION`, while its twin `enable_prefix_caching=False` stays behind as a `setdefault` in `_finalize_engine_args_dict`. Engine args come out identical, but a consumer reading `cache_config` directly — the entire point of the structured config — sees `disable_hybrid_kv_cache_manager=True` next to `enable_prefix_caching=None`. Put both defaults in the same place; the structured config is the better home now that it owns one of them.

### 6. Three engine_extras keys are silently dropped while everything else hard-errors
`vllm_omni/config/omni_config.py:64` and `:934`

`hunyuan_image_3_moe.yaml:39-41` sets `is_comprehension: true` / `final_output: true` / `final_output_type: text`, and the YAML's own comment says stage 0 "must be marked True for the serving path to set AR seed/stop_token_ids." The topology says `owns_tokenizer=False`, so the typed path resolves `is_comprehension=False`.

I checked and this is **not** a regression — `StageConfig.to_omegaconf()` (`stage_config.py:1063`) already overwrites the top-level key from topology, and `serving_chat.py:3060` even documents that the engine_args-nested copy is invisible. So legacy is effectively `False` too. But the inconsistency is worth closing: everything else unowned raises, these three vanish. At minimum log a warning when they appear in `engine_extras`; ideally fix the shipped YAML, since it's currently asking for behavior it doesn't get.

## Nits

**7.** `_project_omni_config_fields` (`stage_init_utils.py:768`) skips every `None`, so the typed representation can't express an explicit `None` for `Any`-typed fields (`attention_backend`, `hf_overrides`, `dtype`). Fine for now given the defaults, but worth a docstring line so a future field with meaningful-`None` semantics doesn't get silently swallowed.

**8.** Diffusion `parallel_config` (`stage_init_utils.py:836`) materializes all 17 defaults where legacy emitted only what the user set — e.g. `--tensor-parallel-size 2` on `wan2_2_ti2v` gives legacy `{'tensor_parallel_size': 2}` vs the full typed dict. I diffed `OmniStageDiffusionParallelConfig` against `DiffusionParallelConfig` field by field and they agree today, and both derive `sequence_parallel_size` identically (`init=False` post-init on the Omni side), so this is currently value-neutral. But it pins one default set to the other with nothing enforcing it — add a test asserting the two default sets match, or the next `DiffusionParallelConfig` default change becomes a silent behavior fork.

**9.** `build_engine_args_dict` is now a pure pass-through whose docstring says callers should "not bind directly to a representation-specific implementation" — while the two comments added at `stage_runtime.py:373` and `serve.py:938` spell out the exact legacy binding it's meant to hide. Harmless, just redundant; one of the three can go.
