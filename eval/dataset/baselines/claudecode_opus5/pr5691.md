# Review: PR #5691 — [Model] Add MiniMax H3 diffusion support

## Verdict: **Request changes**

This is a large, generally well-structured model addition (~7.4k lines). The packed-sequence layout, the RF scheduler, and the DiT itself read carefully and the CPU unit tests are good (I ran `tests/diffusion/models/minimax_h3`, `tests/diffusion/attention/test_flash_attn.py`, `test_ring_fa4.py`, and `tests/entrypoints/openai_api/test_video_server.py` locally — 106 passed, 1 skipped).

Three things should block merge: a **documented `--text-encoder-tp-size` value crashes at startup**, **ring SP silently produces wrong attention** for this model, and the **text-encoder loader downgrades a missing-weight checkpoint to a warning**. The rest are follow-ups.

## Blocking

### 1. `--text-encoder-tp-size N` crashes every DiT rank outside the encoder group when `1 < N < dit_world`

`vllm_omni/diffusion/models/minimax_h3/pipeline_minimax_h3.py:561-579`

`_build_text_encoder_group` calls `init_world_group(ranks=list(range(N)))` on *every* DiT rank. But `GroupCoordinator.__init__` (`vllm_omni/diffusion/distributed/group_coordinator.py:109-122`) only sets `self.ranks`, `self.world_size`, `self.cpu_group`, `self.device_group` when `self.rank in ranks`, and then does:

```python
assert self.cpu_group is not None
assert self.device_group is not None
```

So on a 4-GPU server with `--text-encoder-tp-size 2`, ranks 2 and 3 raise `AssertionError` during pipeline construction. The docstring's premise ("ranks outside the group never run encoder collectives") is true, but they never survive construction to get there. This is exactly the case `_SingleRankEncoderGroup` was written to dodge for `N == 1` — it just wasn't generalized.

The recipe advertises the broken values: `recipes/MiniMaxAI/MiniMax-H3.md:151` — *"valid values on a 4-GPU server are 1, 2, and 4"*.

**Fix:** still call `torch.distributed.new_group` on every rank (it is a collective over the default group), but return a non-member stub — mirroring `_SingleRankEncoderGroup` — on ranks outside the encoder rank set, instead of a `GroupCoordinator`.

Also at `pipeline_minimax_h3.py:235` — `ranks: list[int] = [0]` is a mutable **class** attribute on `_SingleRankEncoderGroup`; make it an instance attribute.

### 2. Ring sequence parallelism silently discards the packed-document boundaries

`vllm_omni/diffusion/models/minimax_h3/minimax_h3_transformer.py:405-419`

The DiT publishes `cu_seqlens_q/k` + `max_seqlen_q/k` via `AttentionMetadata.extra`, plus a fallback `attn_mask`. Only `FlashAttentionImpl.forward_cuda` reads them (`vllm_omni/diffusion/attention/backends/flash_attn.py:277-291`). `RingParallelAttention.run_attention` (`vllm_omni/diffusion/attention/parallel/ring.py:93-165`) ignores **both** `extra` and `attn_mask` and calls `ring_flash_attn_func` on the full tensor.

With `--ring N>1`, the up-to-63 alignment padding rows become attendable keys for every query. They are not benign zeros: their `token_tags` is `-1`, clamped to `0` at `minimax_h3_transformer.py:1057`, so `_modulate_scale_shift` gives them the video-modality `shift` (`:674`) — non-zero content that dilutes the softmax on every real row, every layer, every step.

`MiniMaxH3DiTModel.__init__` validates `ulysses_degree` (`:851-859`) but never `ring_degree`, so this is accepted silently. The recipe only uses `--ring 1`, so this is untested-and-wrong rather than tested-and-wrong.

**Fix:** raise in `_validate_tp_config` when `parallel_config.ring_degree > 1` (matching the existing `cfg_parallel_size` guard at `pipeline_minimax_h3.py:276-277`), or thread `cu_seqlens` into the ring path.

### 3. Text-encoder weight loading treats a broken checkpoint as a warning

`vllm_omni/diffusion/models/minimax_h3/encoder.py:1021-1027`

```python
missing = sorted(set(params) - loaded)
if missing:
    logger.warning("MiniMax H3 text encoder weights not loaded (retained-layer subset): ...")
```

Every parameter is allocated with `torch.empty` (`encoder.py:81`, `:129`, `:170`, …), so any missing shard yields uninitialized memory and a plausible-but-garbage video. The "retained-layer subset" framing doesn't apply: `_map_weight_name` (`:955-993`) already filters `lm_head`, `model.language_model.norm`, and layers ≥ 50, so `missing` should be empty on a healthy checkpoint.

**Fix:** raise. Compare with the DiT side, which does enforce this (`minimax_h3_transformer.py:894-896`, `_mark_missing_params_required`).

## Should fix before/soon after merge

### 4. Reference-video sampling is one ffmpeg process per frame, with a linear seek each time

`vllm_omni/diffusion/models/minimax_h3/reference_video.py:225-244`

Each sampled frame spawns a fresh `ffmpeg -i <video> -vf select=eq(n\,N) -frames:v 1`, and `select=eq(n,N)` decodes from frame 0 every time. A 15 s reference at 24 fps sampled to 2 fps is ~30 launches with O(n²) total decode. On top of that, `_probe_video` (`:28-46`) uses `-count_frames`, which fully decodes the file, and it's called twice per video (`:159` and `:208`).

This all runs inside the request path. `load_video_frames` (`:182-198`) already decodes the whole clip via decord/PyAV — reuse it and index the sampled positions, or emit one ffmpeg call with `select='eq(n\,a)+eq(n\,b)+...'` and `-vsync 0`.

### 5. Distributed VAE encode hands rank-0 temp paths to other ranks

`vllm_omni/diffusion/models/minimax_h3/pipeline_minimax_h3.py:739-771`

When `vae_patch_parallel_size > 1`, rank 0 `broadcast_object_list`s the `prepared_videos` dicts and every rank calls `load_video_frames(item["prepared_path"])`. Those paths live in **rank 0's** `tempfile.TemporaryDirectory`, created per-process at `:1076`. It works single-node only because `/tmp` is shared, and it races rank 0 leaving the `with` block. Broadcast the decoded frames (or the encoded rows) instead of paths, or derive a deterministic shared workdir.

### 6. `num_inference_steps` performs N−1 denoise steps

`vllm_omni/diffusion/models/minimax_h3/time_request.py:44-60` builds `linspace(1.0, 0.0, num_steps)` — `num_steps` sigma *points* — and `minimax_h3_denoise_loop` (`denoise_loop.py:190`) runs `len(sigmas) - 1` iterations. So `--num-inference-steps 50` is 49 model evaluations, which diverges from the `num_inference_steps` contract everywhere else in the project. The recipe calls them "50 sigma points," so this may be deliberate; if so it needs an explicit note at the API surface, otherwise it should be `linspace(1.0, 0.0, num_steps + 1)`. Related: `unique_consecutive` at `:54` can silently shrink the schedule further for large `shift_scale`.

### 7. `_is_blackwell()` misfires on ROCm and runs at import time

`vllm_omni/diffusion/attention/backends/utils/fa.py:26-31`, used at `:63` and `:129`

`capability.major >= 10` is also true for RDNA3/4 (gfx11xx/gfx12xx report major 11/12 through `torch.cuda.get_device_capability` on ROCm), and `is_flash_attn_installed()` is reached from `vllm_omni/platforms/rocm/platform.py:69`. Nothing breaks today only because `flash_attn.cute` isn't importable there. Gate on `current_omni_platform.is_cuda()` too, and consider `@lru_cache` + lazy evaluation rather than a device query at module import.

### 8. Temp-file lifetime and unbounded uploads in the new `input_references` path

`vllm_omni/entrypoints/openai/api_server.py:2957-2974`, `:3113-3117`, `:3126-3130`

- `_persist_uploaded_video_references` applies no count or size cap; a multipart POST can write unbounded data to the server temp dir. `MiniMaxH3Pipeline`'s own metadata sets `max_multimodal_image_inputs=1` (`model_metadata.py:39-42`) — the video side has no equivalent bound.
- Files created at `:3115` are cleaned only on the audio-decode failure path (`:3128`). If `VIDEO_STORE.upsert` / `asyncio.create_task` at `:3167-3182` raises, or the client disconnects before the background task starts, they leak. The happy path is covered by the new test, the error paths aren't.

## Minor

- **`update_audio_mask` is plumbed but never supplied.** `minimax_h3_transformer.py:1099-1101` honors it and `MiniMaxH3DenoiseBranch` computes `audio_update_mask` (`denoise_loop.py:54-57`), but `static_kwargs` (`:71-89`) never passes it — ref2va reference-audio rows come back unmasked. Harmless today (`:211` re-selects and `:234-235` resets the anchor), but a latent trap. Pass it or drop the kwarg.
- **`torch.backends.cuda.enable_cudnn_sdp(True)` is global and never restored** (`encoder.py:1182`). The DiT runs in the same process. Compare `_AudioVAEDeterminismContext` (`vae.py:56-92`), which does save/restore properly.
- **fl2va tokenizes the prompt twice** — `pipeline_minimax_h3.py:514-523` calls `minimax_h3_multi_image_presentation_ids` and `..._token_tags`, each running the full `_multi_image_presentation` (`presentation.py:110-129`). Every other path returns `(ids, tags)` in one call, and `presentation.py`'s docstring says the shared accumulator exists precisely so the two "cannot drift apart." Add a combined entry point.
- **Dead parameter `sp_seq_lens`** at `minimax_h3_transformer.py:428` and `:654` — never read, never passed (`:1070-1078`). Remove.
- **Unrelated doc regression:** `docs/user_guide/diffusion/attention_backends.md:17` drops "and **SAGE** quantized attention" from the `TRTLLM_ATTN` row, while the same file still carries a full `## TRTLLM_ATTN SAGE Quantization` section at line 170. Restore it. The added "LTX-2.0: `CUDNN_ATTN` crashes under torch.compile" subsection is also unrelated to MiniMax H3 — fine content, wrong PR.
- **Test naming:** `tests/diffusion/models/minimax_h3/test_minimax_h3_e2e.py:16` gates a `t2va` test on `VLLM_TEST_MINIMAX_H3_FL2VA_MODEL`.
- **Stray whitespace churn** in `tests/diffusion/attention/test_flash_attn.py:22` (blank-line removal unrelated to the added tests).
