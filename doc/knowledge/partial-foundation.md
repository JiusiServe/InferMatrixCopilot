# Explicit partial foundation publication

The default initialization workflow requires all six foundation facets for every
catalog feature. `--foundation-mode partial` is an explicit alternative for an
existing, source-pinned subscription batch whose genuine native tasks have
already finished. It reconstructs approved sections and inspects the declared
scope without calling either model again. Unknown sections remain unknown;
local publication exclusions retain their original native evidence archives.

Publication still requires the configured production-file threshold, valid
catalog and source inventories, genuine native proofs, valid knowledge files,
and a complete terminal scope. Missing initial feature tasks block publication
unless that feature was already covered in the merged baseline. The external
immutable receipt records the original generation identity, source/catalog and
policy, terminal tasks, active approvals, exact output hashes and unknowns.
Prepared publication retries recheck these bindings and the actual pinned
coverage before writing. Publication status describes PR transport: the
foundation target remains false when six-facet gaps remain, and
`init_complete` remains false.

After this foundation PR merges, start a **new depth batch** with
`--foundation-mode partial --foundation-record /path/to/original/knowledge.json`.
The original published record and receipt, merged output bytes and fixed source
pin become immutable depth inputs. The campaign and standalone depth audit use
the same structural prerequisite; six-facet foundation completion is reported
separately. The audit also requires native approval reports in this mode.

This option preserves the catalog and all semantic acceptance criteria. Each
feature must have recognized depth knowledge, each of the seven depth facets
must exceed the policy threshold, and production coverage must meet the policy
target. The denominator remains the complete frozen catalog times seven.
Partition workers report their actual execution scope separately from global
semantic completion; completing a partition never implies the whole catalog
has passed. Retrieval, independent review and CI remain delivery gates.
