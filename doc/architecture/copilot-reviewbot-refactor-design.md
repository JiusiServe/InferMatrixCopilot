本设计细化并收紧上一版跨仓库重构方案，以共享函数、状态所有权和可删除的实现作为实施单位。终态仍由 Copilot 承担评审与知识执行，bot 管理 GitHub 业务；实施时采用小块替换，避免增加新的总控层。

## 1. 抽象与职责边界

只有同语义、同不变量的功能才共用实现。共享机制不意味着合并权限、账本或业务策略。

| 类型 | 适合承载的内容 | 边界 |
|---|---|---|
| 领域对象 | 页面、规则操作、来源证据等不变量 | 不负责调度和模型运行 |
| 纯函数 | 解析、校验、金额计算、内容变换 | 显式输入输出，不访问运行环境 |
| 有状态服务 | 运行、锁、账本、模型会话、发布 | 每份状态只有一个权威所有者 |
| 边界适配器 | SDK、CLI、GitHub、模型协议转换 | 转换参数和结果，不再实现业务循环 |

优先扩展已有函数和服务。只有需要维护独立状态、资源或领域不变量时才增加类。

细查代码后，上一版有三处应收紧：

- 预算只共享调用预留与结算机制，API、原生会话、审核策略分别保留。
- 结果组装与 SDK 解码分别承担持久事实读取、外部输入校验，保留这两个边界。
- 页面追加、完整报告、简报等有不同格式契约，保留小型呈现函数，共用其中相同的判断。

## 2. 共享单元与删除目标

| 共享单元 | 具体调整与删除 | 保留的业务差异 |
|---|---|---|
| SDK 数据契约 | 保留同一套 DTO；实现类改为延迟加载，修复当前聚合入口造成的冷启动循环导入 | 公开导出、类身份、签名和序列化 |
| 规则校验 | 共用 section、长度、来源形状和新 ID 检查；删除 proposal 与持锁 apply 中重复的检查体 | catalog 范围、代码围栏、tombstone 的不同扫描规则 |
| 评审复查校验 | provider、SDK、bot 发布器调用同一个 recheck 校验函数，删除 bot 第二套检查循环 | 发布时仍重新检查当前状态 |
| 候选处置证明 | 补齐 SDK 结果中的处置记录，共用“被禁止的候选是否进入最终结果”检查 | Direct 历史评论关系与 Strict 候选处置分别表达 |
| diff 区域读取 | 先扩展现有索引，替换重复的文件头、hunk 起点读取 | UT、风险、覆盖判断各自保留 |
| 预算调用机制 | 使用已有 `reserved_call`，移除 `BudgetedLLM` 及重复调用包装 | 每日、每周、阶段和 MoA 的额度及账本 |
| 模型传输 | judge 与 bot 使用已有 provider transport，删除各自命令构造、流解析和会话控制主体 | 权限、超时、模型独立性和 fallback |
| 知识有限修复 | 共用现有 bounded attempt 循环，删除 bot 第二套生成与修复循环 | 修复身份约束、来源审核、空结果判定 |

实施已修复知识追加的跨页面新 ID 冲突：共享校验在任何写入前检查整个候选集合，持锁复验继续保留并发 stale 检查。

### 固定的兼容边界

- 保留 v1 `_updated_page`：仅更新 `updated` 并追加原文，保持原内容和空行字节。
- 保留生命周期 `apply_operations`：继续维护 footer、sources、index 和 tombstones。
- 共用规则校验，但预检与持锁后的复验都执行；保留错误顺序、拒绝索引和公共错误格式。
- 结果组装器读取持久事实，SDK decoder 校验外部 wire；只共享具体字段和领域检查。
- 完整报告、简报、inline 和 fallback 保留各自呈现契约，不引入万能模板引擎。
- 缺失或截断的 diff 保持“不完整”状态，不能作为完整检查的证明。

## 3. 执行与恢复

### 评审调用链

```text
bot：冻结业务输入、路由
    → 隔离 SDK Host
    → 现有 runtime / RunService
    → WorkflowExecution / Executor
    → Direct 或 Strict 的领域步骤
    → 结果
    → bot ReviewPublisher
```

`ReviewRuntime` 从现有 `StrictRuntime` 实现推广，旧名称保留兼容入口，二者共用实现。Direct、Strict 可以使用不同步骤计划，但共用预留、运行身份、状态查询、模型机制和领域校验。

bot 最终保留：

- 触发、队列、路由、业务重试及历史评论收集。
- `provider_run_id`、任务状态和发布回执。
- 当前 PR/head 检查、知识撤回检查及 GitHub 写入。

Copilot 承担知识计划、注入、模型执行、有限修复和完成验证。Direct 的上下文绑定持久保存，恢复不依赖进程内缓存。

请求绑定精确 head、证据、策略版本、已登记执行配置和业务幂等键。执行配置来自可信部署配置；PR 内容不能指定任意命令或工具权限。SDK Host 保持执行侧凭据隔离与只读权限，`RunService` 的只读授权范围不扩大。

两种评审统一保存 `provider_run_id`；旧 `strict_run_id` 兼容读取并增量迁移。预留成功但 bot 尚未保存 ID 时崩溃，仍由同一业务幂等键找回原运行。

### 知识调用链

```text
初始化：prepare → draft → validate → prepare_publication → publish
维护：选择与认领 → 复查业务单元 → 纠错业务单元 → 发布与传播确认
```

Executor 管理步骤进度；初始化记录和维护 SQLite 管理业务事实；Scheduler 管理夜间周期与租约。维护的选择、聚合与账本续跑循环有业务意义，保留在知识域。

`KnowledgeCurator.curate` 仅组合 prompt、共用 attempt、validate、apply。bot 的 clone、artifact、counts、ledger 和交付逻辑继续由 bot 管理。候选本地应用成功不代表独立语义审核或正式发布。

初始化的 placement-before-judge、阶段专属校验，以及维护的原始来源审计、保护规则和撤回决策保留为领域函数。

### 执行内核依赖

`Executor` 只执行注册步骤。自改进的 active release 选择与 handler 装饰在应用组装时完成，移除执行器内对特定步骤名称和自改进实现的依赖。

相关入口：[当前执行器](../../src/infermatrix_copilot/engine/executor.py)。

## 4. 模型与预算的小接口

内部增加预算绑定能力，继续复用已有 `reserved_call`：

```python
bind_call_budget(key, acquire, finish)
call_budget(request)
```

`acquire(request)` 返回领域 reservation；`finish(reservation, facts)` 接收是否发送、可信用量和结束状态。`LLM.create` 与原生 completion 在真实发送位置使用它。共享层传递事实，账户适配器负责估价、持久预留和结算。同一账户按绑定键去重，线程与子进程边界显式传递绑定。

具体删除目标：

- MoA 的 `BudgetedLLM`。
- `for_member` 独立客户端构建，统一委托已有 `for_target`。
- judge 的第二套 CLI 命令、输出解析和工作区控制。
- 知识调用中的重复预算包装。
- 自改进手工构造执行上下文和驱动步骤的路径。

同时修正 MoA 未知费用记零、发送后异常释放预留、实际超支被截断的问题。真实超支完整记账并阻止后续超预算调用；重复结算保持幂等，预算锁不覆盖模型执行。

各领域原有恢复记录继续拥有“已发送但结果未知”的事实，普通步骤重试不能重新派发这种调用。初始化、维护、自改进和 MoA 保留各自账本、额度及退款政策，不另建通用恢复 journal。

judge 迁移有明确前置：共享 transport 必须先通过严格的禁止工具事件测试。fallback、模型独立性、JSON 合法性和来源是否支持结论仍由对应领域判断。

## 5. 提交切片与验证

| 顺序 | 提交内容 | 必须证明 |
|---|---|---|
| 1 | 修 SDK 导入边界 | 冷导入顺序、公开类身份与导出兼容 |
| 2 | 合并规则校验，修跨页 ID 冲突 | 拒绝顺序、proposal ID、并发复验及精确回滚 |
| 3 | 共享 recheck 与处置证明校验 | 旧结果兼容，禁止候选不会进入发布 |
| 4 | 收敛 hunk 区域读取 | 区域顺序、行号和证据文字一致 |
| 5 | 预算绑定，迁移 MoA、自改进及知识调用 | 未知费用、超支、重复结算、并发与恢复 |
| 6 | judge 复用 transport | 先证明禁止工具、权限和模型身份，再删旧实现 |
| 7 | 共用知识修复循环 | 次数上限、修复不丢规则、失败不变成 `no_rules` |
| 8 | Direct/Codex 完整迁入 SDK | 删除 bot Codex 执行路径，验证幂等与崩溃恢复 |
| 9 | Cursor 接入同一 Direct 路径 | 保留 idle/absolute timeout、resume、wrap-up 与修复语义 |
| 10 | 收敛自改进执行路径及残留包装 | 执行内核无领域依赖，旧完整路径删除 |

每批都同时迁移调用方、删除旧函数体。兼容入口只做参数和结果转换，不保留第二条完整执行路径。

公共契约与端到端验证还必须覆盖：

- 旧 SDK 调用、安装包检查及 provider/bot 配对能力检查；新 bot 遇到缺失能力的旧 provider 明确拒绝对应流程。
- 页面字节、历史 finding ID、证据哈希及发布权限兼容。初始化的规范化源片段与维护的精确源片段继续保留各自哈希语义。
- 预留后崩溃、结果落盘后崩溃、发布后结算前崩溃，不重复付费调用或 GitHub 发布。
- 并发预留、跨日／跨周、预算提升、旧待结算记录和持久化失败。
- 撤回对旧快照、缓存、Direct、Strict 和回滚持续生效；保护规则、私有仓库、shadow 与现有熔断保持有效。
- provider 与 bot 完整离线测试。

CI 增加依赖边界检查：bot 只导入公开 SDK，不直接启动评审或知识模型；允许隔离 SDK Host 与必要 Git 操作。执行内核不导入知识或自改进业务，provider 不依赖 bot。

## 6. 收敛与上线门禁

最终按固定基线检查知识模块、全部 provider、bot 的生产代码分别净减少。新增公共代码、兼容代码和运行配置全部计入，测试与文档排除；结合 AST 与实际删除的重复函数体核验。迁目录、删注释、压缩排版不计作收敛，类数仅作辅助指标。

当前知识模块与 bot 已净减少，但全部 provider 生产代码仍净增长；三项门禁尚未全部通过，继续保持草稿。部署配置、预算配置、模型配置和发布权限保持现状。最终数量、执行快照和测试限制见[验收记录](copilot-reviewbot-refactor-validation.md)。

新公共实现纳入维护策略指纹。旧校准、观察周期和撤回演练结果保留，但不能授权新策略。自动维护启用仍须重新校准、完成七个有效夜间观察周期，并通过受审配置 PR；运行任务不自行修改启用配置。
