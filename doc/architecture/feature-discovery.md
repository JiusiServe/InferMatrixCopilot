# 通用功能发现与目录冻结

<!-- verified-against: 2026-10-06 -->

功能发现位于 Skeleton 和 Breadth 之间。仓库适配配置确定扫描范围，源码
commit、范围及库存索引固定后，先阅读已有文档正文，再扫描全部声明范围的
源码和测试。源码轮优先处理原目录没有关联的区域，不限于文档关键词。

## 入口和契约单元

共享库存派生轻量定位单元：Python 的公开符号行段，以及其他语言中的导出、
箭头函数、注册调用、路由、任务和 UI 事件线索。没有可识别入口的文件保留
模块契约线索；未知语言、读取失败和解析失败不会使文件从库存中消失。
这些单元是探索线索，一个函数、文件、配置项或页面不会自动成为一个功能。
全文分片扫描仍然保留，单元分析不能代替完整库存处理。

单元补读包含实际入口和末端行段、同文件中直接提及的辅助定义、导入，以及
包含该符号与断言的测试窗口。所有片段来自固定版本，遵守完整行及字符预算。
这些关联只是定位信息，不构成运行时调用证明或测试覆盖证明；测试未执行。

## 有界补充发现

每个提取 packet 最多返回 24 个候选。达到上限后，将实际 packet 确定性拆小
继续扫描，最多拆分两层；无法拆分或仍满额时保留 `overflow_unknown`，不会
通过重复采样相同 packet 寻求更多候选。

第一轮候选评审后，最多执行两轮残留补扫，针对没有已认可功能映射的入口与
契约单元补读。第一轮与第二轮的上下文预算不同；如果第二轮没有新增证据，
保留未知原因而不重复调用。每轮计划、任务和终态保存于检查点，预算停止后
恢复同一计划，不重复成功扫描。候选的初次评审与三次修正计数跨补扫保持。

只有独立评审认可且引用真实的候选能够解释单元。引用过同一文件、未知候选
或宽泛的目录 glob 不会使该文件中另一个入口被算作已解释。正文引用覆盖多个
入口时，只关联认可说明明确提及的公开符号；单入口引用可以直接关联该单元。
这种关联用于安排补扫，不是完整能力证明。仍未解释的单元
和失败分片随报告交付，不必无限重试，不能声称所有功能已经发现。范围外的
疑似第一方代码只形成建议，自动发现不改变声明范围及覆盖目标。

## 正式目录与证据交接

新增功能必须具有实现证据、独立的行为或契约边界及有效的原生评审记录。
聚合跨前端、后端和 SDK 的同一能力；别名、实现补充、子能力、共享组件、
过期声明与未知单列。原正式功能 ID 不自动删除、合并或拆分。

目录仍经过独立边界及聚合审查，再生成目录 PR。合并后冻结 ID、owner、
边界、路径与 catalog hash，下游阶段使用同一身份。功能数由本仓库决定，
七维分母为当前冻结目录的 `N × 7`；历史目录分母单独保存。

完整报告及紧凑报告包含可携带的 `evidence_bundles`：功能 ID、源码 commit、
scope/index/catalog hash、真实引用行段与内容摘要、unit ID 及原生记录。
只携带定位引用，不内联重复源码或模型正文，也不把发现认可当成深度认可。
基础提取与深化可以优先重读这些引用，再补读缺失维度。原生输入、输出、
工具过程和完整发现报告存于 Git 外档案，紧凑报告给出路径、哈希及限制。

增量初始化可以指定已冻结库存内的 `scan_paths`，优先包含改变的路径及调用方、
测试和相关文档。该集合绑定批次身份，正文扫描和残留目标只处理这些路径，
完整库存及功能目录保留。报告用 `scan_mode: incremental` 区分，不把局部处理
称为全仓库扫描；相关测试片段仍可从其余固定库存中补读。删除或范围外的路径
必须由更新入口单独记录，不能静默纳入或从正式目录删除功能。

`complete` 表示全部声明扫描任务及有界补扫具有终态，不表示未知已解决。
后续深度及生产覆盖门槛仍独立判断，不能删除未知功能或缩小分母提高比例。
