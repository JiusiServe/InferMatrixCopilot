# knowledge_service/l1.py —— 规范

<!-- verified-against: 2026-09-30 -->

`LOC ~600 · 知识质量门的确定性一层（L1） · refactor-status: stable`

## 职责
- `check_tree(files)`：尾注合法、supersede 双向一致、tombstone ID 未被复用、
  `_routes.yaml` 合法且引用页面存在。
- `check_changeset(base, head, changes, external_texts=)`：
  - 路径白名单（`knowledge/{repos/<r>,general}/**/*.md`、`_routes.yaml`、`_tombstones.yaml`）
    与文件模式 `100644`；拒绝 `knowledge/{skills,tools,.claude}/`、顶层文件、非 UTF-8。
  - 无新增重复 ID、不复用退役或 tombstone ID、无指向本次退役/删除规则的悬空引用、
    无新增树级问题、页面不超拆分线。
  - 机械项按规则重算：frontmatter 只允许 `updated`（不倒退）与 `sources`（等于
    `expected_sources`）变化；`_index.md` 只允许为新页追加索引行；tombstones 等于本次
    purge 的 ID 且为规范格式。不符即 issue，不能靠判定覆盖。
  - 其余变更分块：`rule`（add / edit / retire / supersede / purge，按段内容哈希）与
    `prose`（页头、非规则段、非规则页、`_routes.yaml`）。每块有稳定 `block_id`，
    供 L2 判定与签名逐块绑定。
  - `external_refs`：知识目录之外引用了本次退役/删除 ID 的文件（配套 PR 流程）。
  - 嵌套 `###` 规则随父规则退役、删除并记入 tombstones；编辑不得增删嵌套 ID；保护状态以
    旧尾注为准且不得被移除；页面类型不得借改 `type:` 退出生命周期；每个新页面都必须在
    同目录 `_index.md` 出现。
  - purge 时序：tombstone 的 `purged_at` 不得等于该规则的 `retired_at`；传入可信的
    `release` 时 `purged_at` 必须等于它。
- `check_changeset(..., bootstrap=)`：仅供 `kb init`（唯一允许的调用方是
  `kb_service/init_stages.py`，测试扫描源码钉住）。只放宽两条：
  - 新目录（base 中该目录下没有任何文件）可以**新建** `_index.md`，产出一个 prose 块；新索引必须
    链接本目录的每个页面和每个子目录的 `_index.md`，已存在的父目录索引必须链接它
    （父索引也是本次新建时由父索引自己报告）。在已有目录新建索引、删除索引仍然拒绝。
  - 共享的 `knowledge/repos/_index.md` 可以被**修改**（登记新仓库），新增/删除仍拒绝。
  其余规则（尾注、frontmatter、`sources`、白名单其余部分、保护规则）不变；默认 `False`
  时行为与原来逐字节一致。
- `check_index_links(base, head)`：init 侧的索引链接检查（索引改成表格或跨目录链接时
  L1 只把它当 prose 块）。对每个新增或改动的 `_index.md`：本次新增的相对链接必须解析到
  head 中的文件或目录、不得逃出知识树（issue `index_link_broken` / `index_link_escapes`；
  URL、纯锚点不算链接，base 已有的链接不重新判定——有些指向 `doc/`）；链接识别行内链接
  （可带 `<尖括号>` 目标与 `"标题"`/`'标题'`/`(标题)`）和引用式链接（定义 `[r]: target` 只在被 `[文本][r]`、`[r][]`、`[r]` 实际使用时才算链接，
  标签不区分大小写），其余无法解析
  的 `](` 一律报 `index_link_unparsed`，不静默跳过；改动的索引不得丢掉
  base 的链接（`index_link_dropped`）；head 中每个新页面、新子目录索引都必须被父索引链接
  （`index_unlinked`，知识树根没有索引）。
  - 代码处理按方向 fail-closed，不实现 Markdown 解析器：解析/逃逸/无法解析检查看**所有**像链接的
    文本（藏在代码里的也查）；“是否链接了新页面”“是否保留了原链接”只认**确定可见**的链接——它之前
    （含本行）没有任何“危险行”——类围栏行（容器前缀后的 ```` ``` ```` / `~~~`）、去掉容器前缀（`>`、列表标记）后
    以 `<` 开头的 HTML 块行（单行闭合注释除外）、留下未闭合标签或 `<!--` 的行——且在所在块（段落、列表项、标题、
    引用，或真表格——空行后开始、第二行是分隔行——正文行的单元格，代码段跨不过单元格）内它之前没有
    反引号；且不在缩进代码（4 列以上缩进；只有同一块内上方有顶层列表项时，缩进的列表项才算嵌套列表）
    或行内 HTML 注释里。导航只认完整链接：未转义、非图片的 `[` 开始的非空标签紧跟
    `(目标)`，且整段链接文本里没有反引号和 `<`（`<目标>` 的尖括号除外）、同一行链接之前没有未闭合的标签
    （引号内的 `>` 不闭合标签；链接/定义的 `<目标>` 与自动链接不是标签）或注释（缺开头 `[`、`[` 被转义、标签为空、图片、标签里带反引号的都不算）。引用式链接：解析检查查该标签的**每一个**定义（哪个生效取决于哪个在代码里）；导航只认只有
    一个定义且该定义确定可见的标签。“保留”也 fail-closed：base 的链接只有在 head 中确定可见，或它所在的
    每个块在 head 中原样存在、且该块之前的危险行也相同时，才算保留；否则报 `index_link_dropped`（把链接挪进代码 =
    丢链接）。
    在真实知识树的 142 个索引上逐一追加一行，无误报。

## 不变量
纯函数；标准库 + PyYAML + `lifecycle`/`ops`，验证包原样携带。段比较忽略尾部空行
（追加段落时前一段多出的分隔空行不算改动）。
